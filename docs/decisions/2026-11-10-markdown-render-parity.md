# ADR-20261110-markdown-render-parity：流式 markdown 只有一条渲染路径，增量结果与全文一致

- 状态：生效中
- 日期：2026-11-10
- 决策人：用户
- 适用范围：Nano 的三处流式 markdown 入口——预览正文、预览中展开的思考、settle 后的助手消息
- 取代：无
- 被取代：无
- 决策来源：2026-11-10 方案期 grill，用户在「一致性标准」上选 A（逐行相等 + 最终消息同路径）；对应 spec [2026-11-10-stream-render-perf](../specs/2026-11-10-stream-render-perf/README.md)

## 决定

- **只有一条路径**：下列三处必须共用同一套「稳定块 + 尾块」分块渲染，不允许预览一套、最终消息另一套：
  1. 预览正文（`src/transcript/model.ts` `previewUnit`）
  2. 预览中展开的思考（同上，`preview.reasoning`）
  3. settle 后的助手消息（`src/transcript/model.ts` 助手消息单元）
- **不变式**：任一时刻，**已稳定部分**必须与 `renderMarkdown(全文)` 的对应行逐行相等（行文本、缩进、tone 一致）；settle 时再对全文校验一次。
  - 允许例外：尾块超过上界被**冻结**时，冻结边界处可能有一处高亮差异（Prism 跨行 token 状态）；该差异必须由 settle 后的全文渲染覆盖，且不得影响行文本与缩进。
- **退化要可见**：分块器无法正确处理的内容（当前是引用式链接定义）允许该文本**所有入口**一起退化为全量渲染，但必须计数并在 `NANO_DEBUG_RENDER=1` 时写诊断。
- **范围止于流式文本**：静态工具结果、展开详情、settle 后的思考不在本决定内（它们已有模型层 LRU，分块渲染对其无收益）。要把分块渲染扩到静态文本，必须先给出实测收益，不能以「统一路径」为名扩面。

## 依据

- 两套渲染必然行为漂移：列表松散度、引用式链接定义、setext 标题在「整段解析」与「按块解析」下结果不同；漂移的表现就是 settle 时版面跳一下，用户看得见。
- 分块器是增量渲染本来就要写的部件，共用不增加成本；分叉反而要长期维护两条路径。
- 外部同款做法：pi `#3785`、hermes `#67236` 均以「稳定块 + 尾块」为唯一增量路径，并把等价性写成测试不变量。
- 尾块上界是必要的：未闭合的长代码块与长表格天然是一整块，没有上界时单次刷新成本仍随块长增长，与「成本不随已稳定文本增长」的目标冲突。

## 否决了什么

- **只要求「肉眼无明显错行」、最终消息仍走全量渲染**：settle 跳版可见，且两套路径的差异会随 markdown 特性增加而扩大。
- **按内容类型各写一套增量渲染**（表格一套、代码一套）：块类型组合爆炸，无法保证等价性。
- **不设尾块上界**：长未闭合块会让单次刷新成本无限增长。

## 接受的代价

- 分块器要处理围栏、表格、列表等边界，并配一致性 property test（随机切点重放、逐行比对）。
- 含引用式链接定义的文本会整体退化为全量渲染（更慢但正确）。
- 冻结边界处允许一次高亮差异，由 settle 覆盖。

## 允许重开的条件

- 分块器被证明无法覆盖某类常用块，且退化到全量的成本不可接受；
- 或单次刷新成本已经与文本长度无关（例如上游改为整段一次性下发），增量渲染不再是收益来源。

## 影响面

- `src/transcript/blocks.ts`（分块、尾块上界与冻结）、`src/transcript/markdown.ts`（`renderMarkdown` 入口）、`src/transcript/model.ts`（`previewUnit` 与助手消息单元）。
- 测试：`tests/unit/blocks.test.ts` 的一致性 property test；`scripts/bench-stream.mjs` 的 `fence` 用例。
- 不在影响面：`thinkingUnit`、工具结果与展开详情、问卷详情。
