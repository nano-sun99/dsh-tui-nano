# ADR-20261028-implementation-language-typescript：实现语言改为 TypeScript，运行形态改为单一 Node 进程

- 状态：生效中
- 日期：2026-10-28
- 决策人：用户
- 适用范围：nano 的全部实现代码、构建、分发与运行时形态
- 取代：无
- 被取代：无
- 决策来源：2026-10-28 用户当场拍板（本会话三项确认卡）；规格 `2026-10-28-nano-v2-ts`

## 决定

nano 的实现语言由 Rust 改为 TypeScript，运行形态由「Rust 窗口进程 + Node 宿主进程 + fd 3/4 上的自造协议」改为「单一 Node 进程，UI 在官方 profile 插件进程内直接渲染」。

具体含义：

1. 不再有独立的 Rust 窗口进程，不再有 `nano.*` 跨进程协议，不再有 fd 3/4 帧传输。
2. 官方 DeepSeek Harness 仍负责 Agent、模型、工具、会话、权限与持久化；nano 仍是其消费者，不重写内核。
3. 启动入口仍是官方 `dsh --profile dsh-tui-nano`；改变的是该 profile 内的插件现在直接拥有界面，而不是向外转发事件。
4. v1 规格（`2026-10-20-nano-v1`）的行为约定冻结为历史并继续作为行为权威；本 ADR 只改实现语言与运行形态，不改业务语义。

## 依据

- 单进程消除了 v1 架构中最大的可维护性负担：一套 70 方法、78 形状、74 错误码的自造跨进程契约，以及围绕它的帧编解码、有界写、挂载账本与双保险版本校验（源码实测：桥接 10,483 行、协议契约 3,459 行）。
- 同语言直接消费官方公开导出，可取到官方随包发布的 29,075 行 `.d.ts`（`bridge/node_modules/@deepseek-ai/` 实测），不必用第二套协议重新表达一遍官方形状。
- 官方许可证为 MIT（`node_modules/@deepseek-ai/dsh-agent/LICENSE`，`Copyright (c) 2026 DeepSeek`），采用其公开导出无授权障碍；本决定只消费公开导出，不复刻内核源码。
- 已有同生态产品以同一形态跑在生产（TypeScript + `react-reconciler` 自写渲染宿主 + 进程内加载官方内核），说明该形态可行，不是实验性押注。

## 否决了什么

1. **保留 Rust 双进程、仅做局部优化**。理由：用户明确要求「尽可能性能好且不要东一块西一块」，双进程 + 自造协议在三候选里碎片最多，且性能面并非最优。
2. **Node 宿主 + Rust 渲染 addon（napi-rs）**。理由：它能把边界税压到可忽略（批量后约 2.3 ns/事件），但仍是两种语言；用户已判定该混合形态的长期迭代成本高于收益。**否决的是本次选型，不是技术可行性**——该方案仍然成立，若将来重新追求渲染极致可重开。
3. **Rust 单语言重写内核**。理由：8–18 人月量级，且产出大概率劣于官方持续迭代的实现；用户明确判定「不太现实」。
4. **保留 Rust 代码并存**。理由：两套实现会各自演进并立即漂移；改为打 tag + 归档分支保留历史。

## 接受的代价

- **丢弃 61,395 行 Rust 与 789 个测试**。其中沉淀的边界知识不随代码保留，须在 v2 实施中重新发现；缓解手段是 v1 规格正文冻结为行为权威，验收项逐条承接。
- **放弃 Rust 渲染带来的结构性优势**：GC 停顿与 JS 事件循环阻塞重新成为性能风险面，且与官方 Agent 共享同一事件循环。承诺不变的是官方侧不被拖慢，变差的是 nano 自身的滚动与动画上限。
- **产品差异化收窄**：全 TypeScript 之后，nano 与其同生态竞品进入同一技术赛道，可辩护的差异只剩设计取向与功能取舍，不再是运行时性能。
- **迁移期无可用产品**：0.1.0 原本未发布，迁移期间仍不可发布；Rust 侧的验收成果不构成 v2 的发布依据。

## 允许重开的条件

出现下列任一可核事实时，可重新讨论实现语言：

1. 在真实长会话与真实模型流式下，v2 的滚动或输入延迟出现用户可感知的持续卡顿，且经实测归因于 JS 运行时（GC、事件循环共享），非渲染逻辑本身。
2. TypeScript 侧的渲染优化已用尽（虚拟化、增量 diff、离屏预算）仍达不到 v1 已验收的观感基线。
3. 官方内核改为提供语言无关的稳定进程外接口，且该接口覆盖 v1 已交付能力的多数。

不以「理论上 Rust 更快」作为重开依据；须附当次实测数据。
