# ADR-20261029-s02-s01-seams：S01 向 S02 开放三处接入接缝

- 状态：生效中
- 日期：2026-10-29
- 决策人：用户
- 适用范围：S01 与 S02 的文件边界、boot 前补丁注入、boot 后功能初始化、正文区渲染与按键/动作分发
- 取代：无
- 被取代：无
- 决策来源：2026-10-29 实施 #87 时发现 S01（α）只交付零件、未交付接线；用户当日选择「改旧 spec 开三道缝」

## 决定

- S01 在四个文件里提供三处**可选**接缝，S02 只能加接线、不能改 α 既有行为：
  1. **boot 前补丁**：`src/boot/assemble.ts` 的 `CoreBootOptions` 增加可选 `extraPatches`，追加在 α 的四个 patch 之后；`src/main.ts` 传入 S02 的 `featureBootPatches(rootId)`（`src/sessions/boot-patches.ts`）。
  2. **boot 后初始化**：`src/app/nano-app.ts` 的 `NanoAppOptions` 增加可选 `features`（S02 的 `FeatureHost`，由 `src/main.ts` 构造 `new Features()` 传入）；首帧前 `await features.start(context)`，关停 drain 阶段 `features.dispose()`。
  3. **界面与按键**：`src/app/App.tsx` 的 `AppSnapshot` 增加可选 `featureBody` 并在正文区渲染；`nano-app` 把 S02 的 `handleKey` 与 S01 未消费的 keymap action 交给 `features.dispatchAction`。
- 接缝只加可选参数与可选钩子；不传 `features` 时 S01 行为、界面与既有单测与 α 完全一致。
- 这四个文件的**行为 owner 仍是 S01**；S02 只拥有接缝本身（参数、钩子、渲染位置）与接缝生效的验收，α 既有行为的回归验收仍归 S01。

## 依据

- α 交付的 `App`/`AppSnapshot` 是封闭快照（`src/app/App.tsx`），`NanoApp` 只构造 S01 自己的组件（`src/app/nano-app.ts`），`SceneRegistry` 生产代码无实例；S02 没有初始化点与渲染位置，按原边界一行界面都上不了线。
- boot 前补丁在 `src/boot/assemble.ts` 的 `prepareCore()` 里构造，`main.ts` 只传参数；不开放 `extraPatches`，S02 的 `terminal-controller` 行与 `storage-domain` 路由无处安放。
- 2026-10-29 spike-0b 实测：补丁行 + 路由 + 探针 + 最小 `sessionController` 适配器能让官方 schedule 在 boot 后挂起并落盘（证据见 `docs/evidence/2026-10-28-nano-ts/beta/`）。

## 否决了什么

- 让 S01 重开一轮补通用扩展点、S02 等待：多一轮串行等待，且扩展点的形状仍要由 S02 的真实需求定义。
- S02 自建入口替换 `App`/`NanoApp`：等于复制一份 S01 的编排与渲染，直接违背「S02 不复制渲染器」。
- S02 只做无界面服务层、UI 全部推迟：S02 的绝大多数验收项都是界面行为，等于把 β 交付不了。

## 接受的代价

- 四个 S01 文件的 owner 规则从「S02 完全不能动」放宽为「只能加接线」；边界靠 spec §1 的枚举约束，不能靠文件名硬挡。
- α 的回归责任需要拆：S01 管既有行为，S02 管接缝生效，跨份验收要分别取证。
- 将来若 S03 也要接线，需要再走一次改旧 spec 卡，不复用本 ADR。

## 允许重开的条件

- S01 之后提供通用扩展点（例如正式的 feature registry），可一次性取代这三处接缝。
- 出现第二个子件也需要 boot 前补丁或有额外的界面槽需求，说明接缝形状不足。
- 接缝导致 α 既有行为回归且无法用可选参数隔离。
