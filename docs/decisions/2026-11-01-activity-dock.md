# ADR-20261101-activity-dock：主活动栏常驻一行，四款鲸尾按模型请求抽取

- 状态：生效中（本次业务选择已确认；随 `2026-11-01-nano-activity-dock` spec 合并进入仓库基线）
- 日期：2026-11-01
- 决策人：用户
- 适用范围：根对话输入框上方活动栏的占位、显隐、动画来源与随机边界
- 取代：无旧 ADR；局部取代的历史 spec 条款列于[本次规格 §2](../specs/2026-11-01-nano-activity-dock/README.md#2-现状权威与取代范围)
- 被取代：无
- 决策来源：2026-11-01 本次对话，用户原话及选择见下；[可复核调查记录](../evidence/2026-11-01-nano-activity-dock/research.md)

## 决定

主活动栏是独立于底部子代理栏的反馈区域，采用以下统一契约：

1. 在根对话输入位上方固定保留一行；没有内容时仍占位。改变内容，不因忙闲伸缩高度。
2. 当前请求确实已有流式正文进入正文显示路径时，收起鲸尾和活动文案；等待授权/选择时用静态提示，不冒充仍在计算。其它真实在途活动显示相应状态。
3. 鲸尾采用用户指定的 `01Virex/dsh-status-rotator` 四款动作：official、wag、sway、twist；保留原始轮廓和时间轴，不用失真的字符/emoji 近似代替。固定版本与播放细节由本次规格约束。
4. 每次模型请求开始，各 25% 抽一种，允许连续同款；请求内 chunk、工具事件、界面重绘和授权恢复不重抽。新的有身份模型尝试属于新请求边界，不按整条用户任务只抽一次。
5. 纳入终端图片播放与清理；支持路径保真播放，不支持图片时降级为状态文字。减少动态效果用静态鲸尾。
6. 主活动栏不改变输入/取消语义，不接管子代理生命周期、正文思考详情或现有错误通知。

## 依据

用户的可核来源：

- 起始要求：「没做事的时候dock依旧占位充当输入框和正文之间的间隔」。
- 动画要求：「我想用这个鲸鱼尾巴的效果取代常规的loading效果」。
- 对终端图片支持选择「纳入」，并补充「这个仓库有四种效果……我期望四种我们都可以用，然后每次思考都随机出现」。
- Twist 对照修正后确认：「现在ok了」。
- 正文流式输出选择：「收起吧，然后这个dock的显隐时机请你为我调研claude code」。
- 随机边界选择：「每次模型请求（推荐）」。
- 规格机制卡：四项机制「全要（推荐）」；规格结构「不拆（推荐）」，随后「不拆，请你给我pr号」。

本地 Claude Code 2.1.88 源码支持“当前正文提供反馈时隐藏 busy、等待人时不忙碌”的方向；其普通模式/brief 分支的占位并不相同。本决定按用户明确要求采用一行，不将某个 Claude 分支的两行占位说成通用行为。当前 Nano 渲染器只有字符网格，图片支持是待实施能力，不是已验证的产品事实。

## 否决了什么

- 忙碌时新增一行、空闲删掉：会让输入位置跳变。
- 用字符鲸鱼或点阵冒充原版：用户已选择纳入保真图片支持；作者对单行转绘的轮廓损失判断见[历史对照截图](../evidence/2026-11-01-nano-activity-dock/archive/initial-original-vs-character.png)及[来源摘要](../evidence/2026-11-01-nano-activity-dock/initial-animation-evidence.json)。这是作者的视觉判断，不是量化保真率或用户逐字评价。
- 每次重绘或几秒定时随机：不符合按模型请求选一次的边界。
- 直接安装上游插件及附带弹幕、随机文案、渐变或调速：超出本次目标。
- 把已显示的正文与持续鲸尾同时作为常规反馈：用户选择正文显示后收起。

## 接受的代价

- 空闲也占一行，正文可用高度相应减少。
- 图片能力增加协议探测、坐标、清除和故障降级的实现及验收成本；不承诺所有终端/中转层都能播放。
- 多次模型请求可能切换款式，也可能连续抽到同款；不承诺四款均匀轮流出现。
- 真实终端验证必须单独完成；浏览器截图和逐帧对照不能充当终端验收。

## 允许重开的条件

- 真终端证据表明保真图片与一行预算无法兼得，或清理/输入保护无法满足。
- 官方请求身份/事件生命周期改变，现有随机边界不再可可靠识别。
- 用户明确修改正文显隐、占位或随机策略，或提出需要覆盖更多界面/终端。
