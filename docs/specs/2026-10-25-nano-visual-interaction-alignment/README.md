## 1. 目标与边界

目标：让真实 Nano TUI 按现有系统交互稿显示，收掉「结构能用但观感不是同一个产品」的问题。验收单位是终端 cell，精确字体和行高继续由终端控制。

范围：

- `/model` 的底部控制层、模型列表、强度粗进度条、覆盖与恢复。
- 主界面在模型面板打开时的底部槽位处理。
- transcript 中过程行、上下文块和代码变更块的布局、对齐、留白、颜色与可视行预算。
- 现有主界面的边距、标题、输入区、底栏、活动行和子代理 dock 的对账回归。
- 深色 / 浅色主题下的视觉 token 与真实终端证据。

不做：

- 不改变模型目录、模型切换、强度提交、官方事件、RPC、协议字段、凭据和数据所有权。
- 不新增 `/effort` 命令；强度继续归 `/model` 的单页交互。
- 不修改会话、技能、任务、调度和项目规矩面板的业务行为；这些面板当前没有对应系统交互稿，本 spec 只记录为无设计依据，不凭感觉换皮。
- 不修改字体、字号、Ghostty 配置、终端透明度或终端原生选择行为。
- 不把浏览器交互稿的像素值直接搬进 Rust；浏览器里的 18px 粗条转换为终端里的粗字符单元格呈现。

## 3. 已确认决定

### 3.1 系统交互稿是视觉权威

系统稿定义结构、层级、留白、边框、焦点、颜色职责和状态呈现。Rust 使用终端 cell 翻译它，不复制浏览器像素。

- 主界面左右保持 2ch。
- 选择面板使用顶端 accent 线和内容留白，不使用居中四边框。
- 正文使用 fg，次要信息使用 muted，焦点和用户输入使用 accent，错误 / 警告 / 成功继续使用对应语义色。
- 字体和字号属于终端；代码只负责 cell 宽度、换行、字重和颜色角色。
- 应用自有装饰性 emoji 保持 0；固定符号沿用现有白名单。

### 3.2 `/model` 底部控制层

打开 `/model` 后，模型面板接管底部控制区域：

- transcript 保持可见，模型面板锚在 transcript 下方。
- 面板宽度为主界面内容宽度，左右 2ch；顶部只有一条 accent 线，不画四边框，不清除 transcript。
- 隐藏输入框、底部权限 / 路径状态和子代理 dock，避免底部出现第二套状态信息。
- 面板关闭后恢复原来的输入、状态和 dock；确认结果只进入底部瞬态。
- 面板获得全部键盘焦点，底层发送、停止、队列和 dock 快捷键不泄漏。

### 3.3 `/model` 内容

面板保持单页：

- 头部左侧是 `模型`，右侧为 `当前：<模型> · <强度>`，两侧垂直居中。
- 模型列表只显示模型名；当前焦点用 `▶` 和 accent/bold 表示，不铺 selected 背景，不显示 provider 标题、行尾当前标记和长描述。
- 多 provider 仍按精确 `provider + model` 提交；单 provider 不渲染 provider 分组。多 provider 且名称冲突时，模型名后补 muted provider 标识。
- 强度区不再显示 `强度 ● XHigh` 说明行，只显示一条铺满内容宽度的粗进度条和四个对齐档位标签：`Low / High / XHigh / Max`。
- 四个档位共用一条连续轨道，档位标签位置与进度位置相同；不画“默认”档，不画细线 + 圆点选择器。
- `Low` 使用 muted 灰色；`High` 使用灰蓝；`XHigh` 使用更深蓝，并让高光从左向右移动；`Max` 使用最深蓝，进度条整体平滑脉冲，`Max` 标签同步霓虹发光脉冲。
- `NANO_REDUCED_MOTION=1|true` 时，XHigh / Max 静止显示，仍保留颜色和档位名称。
- 面板内不常驻键位页脚；键位以 `nano --help` 为长期入口，设计稿仅保留必要的方向操作提示。

### 3.4 代码变更块

代码变更继续是独立的 Edit 内容块，具体呈现为：

- 标题行：`▸ Edit <path>`，`+N -M` 右对齐；Edit、路径、统计之间使用现有 1ch 间距。
- 标题下保留一行 muted 状态（如 `已应用` / `未应用`），标题下加一条 rule 分隔线。
- 行号固定 4ch、标记固定 2ch，代码正文使用 fg；增删行使用浅 / 深主题对应整行背景，增删字符使用行内强调背景。
- 增删背景填满 diff 内容宽度，包括代码末尾的空白 cell；上下文行不增加装饰背景。
- 默认最多显示 8 个**视觉行**；源行换行、CJK、超长单行都按实际显示行计数。隐藏提示显示剩余视觉行数，展开后显示完整 diff。
- 点击内容展开 / 收起，拖选文本不触发展开；已有 `HitKind::Toggle` 语义保留。
- 不新增“复制修改后代码”“展开原始差异”等按钮；复制沿用终端原生选择 / 既有复制路径。

## 4. 保持不变的真实约束

- 模型目录、强度档位和选择结果只来自官方服务；客户端不伪造档位。
- 未显式选择模型默认强度时，不发送 `reasoningEffort`。
- 选择失败、结果未知、目录过期和 writer-held 继续按现有回执与重读逻辑处理。
- 模型切换不取消正在运行的回合，不清空队列。
- 浅色 / 深色主题继续由 `NANO_THEME` 选择，普通背景保持终端默认透明背景。
- 主界面已经对上的标题、2ch 边距、输入上下文占用线、活动行、底栏排列、上下文合并、子代理 dock 和 Markdown 处理不重写业务，只做回归核对。

## 7. 机制清单

| 机制 | 解决什么 | 没有会怎样 |
|---|---|---|
| 模型底部控制层 | 面板打开时统一接管底部焦点和槽位 | 居中弹窗、输入、状态和 dock 叠在一起，页面出现两套层级 |
| 强度粗进度条与档位动效 | 让 Low / High / XHigh / Max 在一条轨道上有清晰位置和强度变化 | 细线、圆点和文字挤在一起，档位不对齐 |
| 模型面板覆盖生命周期 | 打开时隐藏底部状态，关闭后恢复并回传瞬态 | 面板底部被权限 / 路径状态挤高，确认后状态残留 |
| 视觉行预算 | 让 diff 在宽字符和换行情况下仍符合 8 行设计预算 | 源行数和实际占屏行数不一致，窄终端撑爆布局 |
| Diff 整行底色 | 让新增 / 删除的范围一眼可读 | 只有文字后面有色块，行级语义不完整 |

## 8. 自定细节

- 单 provider 时隐藏 provider 分组；多 provider 同名时在模型名后追加 muted provider 标识。
- 粗进度条在终端中使用一行 cell 高的填充字符与主题背景表达，浏览器稿的 18px 只是视觉代理，不增加面板行高。
- 四档进度位置使用 0% / 33% / 66% / 100% 的一致锚点；Low 仍显示可见的低档颜色与标签，不能因为填充比例为零而消失。
- High / XHigh / Max 的颜色使用共享 Palette；Low 使用 muted。具体 RGB 由实现按现有暗 / 亮主题对比度确定并补入主题测试。
- XHigh 的高光从左向右离散移动；Max 的条和文字使用平滑脉冲，不使用突兀的 steps 闪烁。
- 模型面板确认 / 取消后只写底部瞬态，面板本身不保留结果卡。
- 次级面板本次只保留现状，不从缺少设计稿的区域推导统一换皮。
