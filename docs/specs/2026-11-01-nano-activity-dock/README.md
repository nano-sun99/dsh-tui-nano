## 1. 目标与边界

输入框上方常驻一行活动栏，回答「当前是否在执行、在做什么、是否在等我」。执行时可播放四款鲸尾；内容隐藏时仍保留同一行，不让输入框跳位。

**一个完整交付**包含真实终端图片能力、模型/工具/决策事件投影、活动栏布局、四款随机、降级、清理与相关测试。先验证图片能力，再完成接线与联合验收，仍属一个执行 issue；不把阶段拆成多张执行单。

不做：设置页、随机文案/梗、弹幕、渐变扫光、按 token 速度调速、工具触发换款、进度百分比、额外计时/成本栏；不安装 status-rotator 插件、不修改官方依赖、不改变模型或工具执行语义。预览的场景下拉和动效选择按钮不进入产品。

本次只覆盖根对话及其输入位决策等待。子代理详情/列表、模型面板、交互终端保持原有界面语义，不给它们补一套主代理活动状态。正文思考展开规则、底部子代理栏、输入上下文容量线、通知生命周期、提交/停止键位不重做。

## 3. 布局与内容

### 3.1 固定一行

- 根对话：正文/补全 → **活动栏 1 行** → 输入块 → 底栏 → 既有子代理栏。左右各 2ch，与输入块对齐。
- 输入位决策卡：正文 → 决策卡 → **活动栏 1 行** → 底栏 → 既有子代理栏；输入框由原决策逻辑隐藏。
- 容器高度只由该界面是否属于本任务决定，不由 busy/idle/文案/图片能力决定。每种同界面状态切换前后输入框（或决策卡底边）不因活动栏伸缩而移动。
- 将这一行计入共同的正文高度与命中坐标计算。补全弹层、1–4 行现有输入窗口、底部 dock 的各自预算不被活动栏额外重复扣减。不得顺手调整现有输入最大行数。
- 默认图标槽 3ch，图文间隔包含在槽内；文字单行截断，按终端实际单元格宽度处理 CJK。静态等待文字可从活动栏左边缘开始。
- 鲸尾外接正方形不得高于一行或宽于图标槽。20×20px 是浏览器参考，不是终端固定像素值；按实际 cell 像素尺寸等比缩放，不拉伸、不裁去尾鳍。
- 非根对话界面接管时先删除主鲸尾图片，再沿用该界面的布局；返回根对话恢复当前状态，不因重新挂载重抽。

### 3.2 显隐优先级

显示规则与回合生命周期分开；隐藏鲸尾不代表执行结束。按下列顺序选择展示：

1. 非本活动栏所属界面/终端已移交：不画主活动图片，移除已有图片。
2. 当前根对话仍有待答决策：静态「等待你的授权」或「等待你的选择」；计划审阅复用现有语义给静态待审提示。暂停图片，不靠 notice TTL。
3. 当前回合取消请求已发送、尚未确认结束：静态「正在停止…」。不得因 UI 点击停止就显示已结束。
4. 已结束、空闲、终态失败，且没有新提交等待接纳：活动栏内容为空。错误留正文/原通知通道。
5. 当前请求已有非空、非仅空白的流式正文进入正文显示路径：清空活动栏图文、停止图片更新，容器保留。
6. 其余已接纳的工作：按 §3.3 显示活动文案；本请求已抽到鲸尾且图片能力可用时播放。

「正文已显示」指当前请求的流式正文已交给根 transcript 渲染，不是原始 token 到达、历史回答存在或当前屏幕恰好有字；也不按滚动是否在底部判断。Nano 不复制 Claude 的完整行缓冲，不改变原流式输出粒度。用户上滚、resize、主题变更不会触发显隐重新定义或随机重抽。

正文流式预览提交为正式消息时，以同一批状态更新衔接，避免只因 preview 被清空就闪出一帧“处理中”。后续明确的工具执行/模型请求可重新显示；回合结束则保持空白。并发时当前可显示流式正文优先于普通工具文案，决策等待和停止待确认优先于正文隐藏。

### 3.3 文案与触发

| 场景 | 活动栏 | 事件约束 |
| --- | --- | --- |
| 合法提交已接纳，模型请求尚未开始 | 静态「正在处理…」 | 不提前随机，不把正在编辑草稿当执行 |
| 模型请求 start，尚无具体阶段 | 鲸尾 +「正在处理…」 | 按新请求身份抽一次 |
| 当前请求真实 reasoning 内容 | 鲸尾 +「思考中…」 | 不凭等待时长猜思考 |
| 真实工具参数生成 | 鲸尾 +「正在准备工具…」 | 已确认有参数事件才区分；否则通用处理 |
| 工具已执行、结果未齐 | 鲸尾 +「正在运行 <工具名>…」 | 以 callId 跟踪；多个调用用「正在运行 N 个工具…」 |
| 已收到文字但尚未进入正文显示 | 保持处理反馈 | 不提前留白 |
| 当前流式正文已显示 | 空白 1 行 | 本轮仍可停止/插话，键位提示不能变成退出 |
| 等授权/选择 | 静态等待文字 | 关闭/答复后按实时状态恢复，不重抽 |
| 取消尚未确认 | 静态「正在停止…」 | 确认结束后空白，不把工具后台存活误报为完成 |
| 回合结束或终态失败 | 空白 1 行 | 不新增常驻“完成/失败”；停止自有帧更新 |
| 只有子代理工作、主代理空闲 | 空白 1 行 | 子代理由已有底部栏表达 |

工具失败但模型继续恢复，不等于回合终态失败。缺少可靠工具名时用「正在运行工具…」；工具参数不能显示成已执行的命令。不照搬 Claude 专用 Sleep 工具特例，不解析 Bash 字符串含 sleep 来猜显隐。

## 4. 请求身份、随机与过期事件

- 每个**新的模型请求/尝试**开始时，official / wag / sway / twist 各 25% 抽一次；允许连续相同。不使用轮流、不重复抽样或随机定时切换。
- 用官方请求/尝试身份及会话、回合上下文去重。`agent/assistant-stream` 的 start/attemptId 是现有候选入口；实施必须核对已安装官方契约与发射点，测试 start 是否覆盖真实请求开始及重试。网络 request id、用户提交 requestId、流式 revision 不能互相替代。
- 同一 start 重放、chunk、工具执行/结果、授权恢复、主题/窗口变化、组件重建均不重抽；请求间自动重试若有新 attemptId 就是新尝试、应抽一次。底层未暴露的内部重试不自行猜出新请求。
- 请求 start 前只静态处理，避免提交时抽一次、start 再抽一次。请求结束后的工具阶段保留最后一次选择；下一次模型请求再选。
- 有序接收 frame，旧会话、旧请求、已结束回合的迟到事件不能重亮、重抽、清除当前新请求。不得用全局计时器或动画组件 mount 作为请求边界。
- 工具以真实 callId 集合收敛；一个结果不能清掉其它未结束调用。`assistant/message`/stream end 只结束该消息或尝试，不独立证明整个 turn 已结束。
- 切会话、重启、回合终态/销毁时清本范围状态和资源；恢复历史不会播放旧请求。进入正在运行的会话若能取得其当前身份，则按该身份只初始化一次，否则静态处理直至获得可靠 start。

## 5. 四款素材与播放

唯一动作基线：`01Virex/dsh-status-rotator` 提交 `0d486a80c55dabee9e62ce8d87612dc15792c805` 的 `lib/client.js`；精确入口、摘要、许可及证据见[调查记录](../../evidence/2026-11-01-nano-activity-dock/research.md)。

| 动作 | 源时间轴 | 本次固定周期 |
| --- | --- | --- |
| official 官方原版晃动 | 150 帧 | 4 秒（仓库推荐） |
| wag 翻转摆尾 | 24 帧，源循环从第 15 个零基帧开始旋转 | 2 秒（仓库 README 演示） |
| sway 左右摆尾 | 24 帧 | 2 秒（同上） |
| twist 扭转摆尾 | 36 帧，源循环从第 29 个零基帧开始旋转 | 2 秒（同上） |

- 使用源 `TAIL_ANIMATION_POSES` 的完整轮廓、帧序、重复帧、`viewBox 20 40 300 240`、evenodd 填充。不凭印象重画，不用字符鲸鱼、喷水 emoji 或单行点阵替代。
- 本仓采用的 official 为 status-rotator 从 GIF 描出的 150 帧版本，不是早期本机 Harness 60 帧 APNG；二者不能混装或用错误摘要标记。
- 周期内离散逐帧，无自行补间。按经过时间算帧，不按收到 token 数或定时回调次数累计；发生调度延迟可跳到应在的帧，不能拖慢整圈。
- 新请求从所选动作首帧开始；同一请求隐藏/恢复不重抽，动画资源可暂停/重建但不出现旧动作残影或多个播放器争写。
- 只让主鲸尾动；文案不扫光、不循环标点。既有子代理灯是独立既有组件，本次不增改。
- `NANO_REDUCED_MOTION=1|true` 沿用现有约定：静态鲸尾 + 真实状态文字；不是仅隐藏后继续后台刷帧。
- 实施保留 `Copyright (c) 2026 01Virex` 和完整 MIT 许可、固定来源提交、生成/提取说明。只引入所需素材，不把上游插件执行包/整套样例加入依赖。素材更换需要可比对的源与版本，不能静默跟随远端。

## 6. 真实终端图片能力

图片能力是本任务新能力，不能把浏览器 SVG 动画复制进 TUI 就宣称完成。实现可选择当前 Ghostty 支持的协议与预生成图片帧，但须以官方协议和本机实测为依据，在实施证据中记录实际方法、终端版本、素材到像素帧转换和刷新策略。

### 6.1 支持与降级契约

- 必须在真实 Ghostty 普通会话直接运行完成原形鲸尾；仅展示文字是其它终端/能力不可用时的降级，不是 Ghostty 支持路径通过。
- 不能只凭 TERM 名称断言图片能力。能力未知/协商失败/坐标或尺寸不可用时不发送未经支持的图片输出，及时回退静态状态文字；不得把协议回应灌入输入框。
- 非交互输出与未验证的终端/中转层（含 tmux/SSH）不承诺图片支持，安全文字降级；首版不扩为全终端图片平台，不新增用户设置页。
- 渲染器/终端写入通道统一拥有图片位置和输出次序；不得从活动栏组件另起 stdout 写入，与现有字符帧、鼠标命中、光标恢复互相覆盖。
- 图片缓存、已注册资源和定时器必须有界，四款素材可预计算；请求数增长不能持续累积服务器端图片 id 或播放器。

### 6.2 清理与输入保护

- 进入正文可见、静态等待、停止待确认、空闲、失败终态、切界面/会话、终端移交、退出时清除屏幕上的动态图片；减少动态效果时替换成静态图。
- 缩放/滚动重排先清旧位置再画新位置；同一行只有一个主鲸尾。图像不可遮住输入边框、正文、notice 或底部子代理栏。
- 不能因图像帧更新改变用户输入、选区、光标位置或 IME 锚点；深浅主题都以透明底和对应前景可读。
- 图片发送失败只影响图形反馈，不中断 agent、不丢正文/草稿；错误去噪遵循既有通知策略，不每帧刷警告。
- 正常退出/受控重启清图片、计时器、订阅并恢复终端；不可捕获进程终止不承诺清理成功。

### 6.3 首个可行性检查

实施时先在临时/隔离测试入口验证：真实 Ghostty 单行四款连续播放 → 隐藏清除 → resize/主题切换 → IME/输入保护 → 文字降级 → 退出清理。先得到可复现证据，再完成产品接线。若保真图片与一行预算不可兼得、协议能力不足或残影无法清理，应报告具体证据并停止扩大实现，不擅降成字符鲸尾或提高 Dock 高度。

## 7. 改动面、验收与完成标准

### 7.1 改动面

实施允许：`src/app/App.tsx`、`src/app/nano-app.ts`、`src/conversation/controller.ts`、`src/theme/spacing.ts`；按需在 `src/render/` / `src/runtime/terminal.ts` / `src/input/parser.ts` 加最小图像与回应隔离；新增活动状态/素材模块、必要资源与许可；相关 unit/feature/e2e 测试、使用/证据文档。正式新增文件名由实施确定，不另外搭通用图片框架。

`src/transcript/model.ts` 仅允许提供当前流式正文显示事实，不改变折叠/历史/消息内容；`src/decisions/manager.ts` 仅按需公开等待事实，不改审批或问卷答案/取消契约。其它模型、插件、子代理生命周期、通知 TTL 和业务界面不在改动面。

本规格 PR 只新建本 spec、新 ADR 与调查材料；不更新依赖、不带生产实现、不修改既有冻结 spec。

### 7.2 必须可判定的验收

所有项是**实施验收，当前均未完成**；浏览器已有检查只能作为设计证据。

## 8. 机制清单与结构选择

用户已于本次会话选择四项「全要」；不因新增内部状态或测试场景另扩产品机制。

| 机制 | 解决什么 | 没有会怎样 |
| --- | --- | --- |
| 常驻一行活动栏 | 分隔正文与输入，容纳当前反馈 | 忙闲切换跳位或正文贴输入框 |
| 真实事件驱动的显隐投影 | 区分工作、正文反馈、等待人、停止待确认 | 假忙碌、重复反馈或误报结束 |
| 每个模型请求四款等概率抽一次 | 按用户期望变化、同请求稳定 | 重绘乱换或整任务一直同款 |
| 终端图片播放/清理与文字降级 | 原形鲸尾且不污染输入/其它界面 | 字符失真、残影或不支持终端乱码 |

体量评估：可拆候选为「图片播放/清理」→「活动栏事件与随机」，前者可单独验证，后者消费其能力，最终需联合验收。用户明确不拆，因此 1 份 spec + 1 张执行 issue；保留先能力验证、后接线验收的先后，不创建父单或阶段执行单。文档审查、实现、测试、PR 不算新的产品交付。

## 9. 自定细节

以下为本次规格默认值，不伪装成用户逐项指定；在审核时可修订：

- 图标槽 3ch；容器一行、左右 2ch；终端图形尺寸从 cell 推导，不锁 20px。
- official 4 秒、其余 2 秒，取源仓库推荐/演示值；没有速度设置。
- 请求开始前静态处理；工具并行以计数文案表达；未知阶段用通用处理，不新增网络故障猜测。
- 决策等待优先、取消待确认其次；当前正文进入显示路径后隐藏，不跟滚动偏移来回闪。
- 请求身份优先复用官方 start/attemptId，具体生命周期须实施首步核实；未暴露的传输重试不额外造身份。
- 主根对话为本次范围；已有正文替换面板不显示主活动；图片协议具体技术选型以真 Ghostty 试验和官方文档为据，不从浏览器能力推定。
- 等待文案从问卷 notice 挪到活动栏属于本规格明确的局部扩展；其它 notice 仍遵循原 ADR。
- 无需新增用户配置或后台轮询来控制显隐；现有主题与 reduced-motion 配置复用。
