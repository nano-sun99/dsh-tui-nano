## 2. 已核实事实与参考

基线：`68e3ce5`（origin/main，2026-10-30）。

### 2.1 现场症状与代码根因

- **没有列布局**：表格分支把每行单元格用 `' │ '` 拼成一条文本，再交给 `wrapSpans` 按总宽折行（`src/transcript/markdown.ts:96-108`）。列宽、列对齐、表头分隔都不存在。
- **折行后列归属丢失**（实测，60 列以内必现）：宽度 46 时同一张表渲染成
  `0.2.0 发布 │ 未发布到 registry │ 结论见` / `docs/release/0.2.0/`，第二行看不出属于哪一列；宽度 80 时各行 `│` 也对不齐。
- **单元格样式丢失**：单元格取 `cell.text`（`markdown.ts:97,99`），`**粗体**` 与 `` `code` `` 在表格内退化成纯文本。
- **嵌套列表不成立**：实测 `• a / • b / • c / • d` 缩进为 0/2/4/6，逐层正确；有序项 `10.` 的 marker 宽 4、子项缩进 4，符合「随 marker 宽递增」。本项从原范围撤出，规格不含列表改动。

### 2.2 参考实现（同行做法）

- **Claude Code 2.1.88**（本机解包源码，仅作行为依据）：`src/components/MarkdownTable.tsx` 三段式列宽——每列先算 `min`（该列最长单词宽）与 `ideal`（整格内容宽）；`Σideal ≤ 可用宽` 用 ideal，否则各列取 min、余量按溢出比例分配；仍放不下则按比例压缩并允许硬折词。`MIN_COLUMN_WIDTH = 3`、`SAFETY_MARGIN = 4`、单格折行超过 `MAX_ROW_LINES = 4` 时整表转纵向键值格式；表头居中，数据按 `align` 对齐；外框 `┌┬┐ ├┼┤ └┴┘`。
- **Glamour（Charm 的终端 Markdown 渲染器）**：`ansi/table.go:106-123` 显式把 `BorderTop / BorderLeft / BorderRight / BorderBottom` 全部关掉，**只保留内部网格**——成熟终端渲染器默认不做外框。
- **Rich**：`rich/box.py` 里最克制的三档是 `SIMPLE_HEAD`（只有表头下一条线）、`SIMPLE`（顶线 + 底线）、`MINIMAL`（只留列间竖线，四角断开）。
- **booktabs（学术排版）**：去掉竖线、顶/底用粗规则、中间用细规则、加大行距，理由是可读性而非装饰（https://nhigham.com/2019/11/19/better-latex-tables-with-booktabs/）。

### 2.3 为什么选 C 而不是全框线

- 视觉语言复用：nano 现有排版词汇只有 `─`（分隔线）与 `│`（引用块），C 只新增一个 `┼`；全框线一次引入 6 个新字形，且在终端里把表格做成嵌入式小部件，与工具卡、diff 块抢同一种语言。
- 中文必须留竖线：中文无空格，折行按字断；一旦某格折成两行，没有竖线就分不清归属（booktabs 的前提是西文可断词）。
- 宽度预算：3 列时全框线开销 10 格（Claude Code 自己的公式 `1 + 3×列数`），C 为 6 格，纯三线为 4 格。

## 3. 目标行为

### 3.1 表格骨架

1. 字符集只有三个：列分隔 `│`、表头分隔线 `─`、交叉点 `┼`；全部用 `faint` tone。**不画外框、不画数据行之间的分隔线、不画底线。**
2. 布局为：表头行 → 表头分隔线 → 数据行。表头行与数据行之间只隔这一条线，线宽等于表格总宽。
3. 单元格左右各留 1 个空格；因此相邻两列之间固定 3 格（空格 + `│` + 空格）。首列前、末列后不加空格。
4. 表格前后各留 1 个空行（与代码块一致）；连续空行由现有 `trimBlankRows` 去重。
5. 表头用 `accent` + `bold`，对齐方式与数据列相同（见 3.2 第 3 条），不额外居中。

### 3.2 列宽分配

1. 对第 i 列：`min_i` = 该列所有单元格「最长不可断片段」的显示宽度，下限 3；`ideal_i` = 该列所有单元格纯文本内容的显示宽度，下限 3。宽度一律用现有 `graphemeWidth`（CJK 记 2 格）。
2. 可用宽 `W = width - (列数 - 1) × 3`；若 `W < 3 × 列数`，直接进入 3.3 的兜底。
3. 分配顺序：`Σideal ≤ W` → 用 ideal；否则 `Σmin ≤ W` → 各列取 min，余量按 `(ideal_i - min_i)` 的比例分配（向下取整，余数补给溢出最大的列）；否则按 `Σmin` 比例压缩到 `W`，每列不低于 3，并启用硬折（允许在任意字素间断行），中文不受影响（本来就按字断）。
4. 表头行与数据行共用同一份列宽；表头分隔线用 `─` 填满每列宽度，列间补 `┼`。
5. 单元格内容用现有 `wrapSpans` 在列宽内折行；行高取该行各单元格折行数的最大值，行高较小的单元格垂直居中（上下均分空格，多出的 1 行在下）。
6. 每行末尾不留尾随空格。
7. 不引入 Claude Code 的 `SAFETY_MARGIN`：nano 的 `width` 是调用方已扣除缩进的实测宽度，不存在 Ink flexbox 的抖动前提。

### 3.3 窄屏兜底

1. 触发条件（任一成立即整表转纵向）：`W < 3 × 列数`，或任一单元格按列宽折行后超过 3 行。
2. 纵向格式：每条记录若干行，字段行形如 `列名  值`（列名 `faint`，值 `normal`），列名后固定 2 格；值超宽时在可用宽内折行，续行缩进 2 格。
3. 记录之间用一条 `─` 分隔（宽度取可用宽），最后一条之后不加线。
4. 纵向格式不使用 `│` 与 `┼`。
5. 阈值 3 是按中文可读性定的（Claude Code 用 4，前提是西文可断词）；落进 `自定细节`。

### 3.4 单元格行内样式

1. 单元格内容改走 `cell.tokens` → `inlineSpans`，粗体、斜体、删除线、行内代码、链接沿用现有行内规则。
2. 列宽与折行按纯文本计（`rowText` 去样式后的显示宽），样式不影响布局。
3. 表格单元格内的 `codespan` 不加两侧空格（正文里的 ` x ` 在表格里会把列撑开）。
4. 单元格内出现块级内容（列表、代码块、嵌套表格）时，降级为纯文本拼接：按 `cell.text` 原样输出，不递归渲染块。
5. 空单元格输出为空字符串，列宽仍按该列其他单元格计算。

## 4. 改动面与不做事项

改动面：

- `src/transcript/markdown.ts`：替换 `case 'table'` 分支；列宽、折行、兜底抽成文件内独立函数（不新建包）。
- `src/transcript/spans.ts`：仅在需要补「按显示宽补齐空格」的辅助函数时改动；`wrapSpans` 的断行规则不动。
- `tests/unit/`：新增表格用例（见 §5）。
- 文档：本规格；`docs/release/0.2.0/known-limitations.md` 不涉及。

不做事项：

- 不画外框、不画行分隔线、不加排序 / 展开 / 折叠等交互。
- 不支持 HTML 表格（`<table>` 仍按现有 html 分支输出纯文本）。
- 不改代码块、引用块、列表的既有样式；不改 `wrapSpans` 的断行与裁尾规则。
- 不做表格内容缓存或增量重排；不做每列最大宽的手动配置。

## 5. 有限验收

1. `npm run typecheck` 与 `npm test` 全绿。
2. 新增单元测试覆盖：宽表（`Σideal ≤ W`）、需压缩（`Σmin ≤ W < Σideal`）、需硬折（`W < Σmin`）、窄屏兜底、中文与英文混排、单元格行内样式、空单元格、对齐三态、表头分隔线宽度、尾随空格。
3. 折行归属：任意列单元格折成两行时，第二行仍落在该列宽度内，相邻列不错位。
4. 真终端目测一次：60 列与 100 列各一张含中文的表格，确认 `│` 逐行对齐、无外框、兜底触发正常。
5. 不承诺像素级截图取证（与 0.2.0 现有证据口径一致）。

## 6. 机制清单

| 机制 | 解决什么 | 没有会怎样 |
|---|---|---|
| 列宽分配 | 每格按本列宽度折行，竖线逐行对齐、折行后归属不丢 | 就是现状：所有格拼成一行按总宽折，第二行起看不出属于谁 |
| 窄屏纵向兜底 | 列多 / 列窄到无法读数时，整表换成「列名 值」逐行列出 | 60 列里 5 列，每列只剩 3–5 格，中文碎成一行一字 |
| 单元格行内样式 | 表格里的加粗、行内代码、链接保住样式 | 现状：`cell.text` 取纯文本，样式全丢 |

三项均由用户 2026-10-30 机制卡选择「全要」。

## 7. 自定细节

- 规则线 tone 统一 `faint`；表头 `accent` + `bold`（沿用现有 heading 用色）。
- 单元格内边距 1 格（不取 `INLINE` token：token 体系管的是块间距，表格内边距是字符级留白，写死 1 并在测试里固定）。
- 表格前后空行：各 1 行，与 `renderCode` 一致。
- 兜底阈值：折行超过 3 行即转纵向（Claude Code 取 4）。
- 兜底字段行格式：`列名` + 2 格 + `值`；续行缩进 2 格。
- 列宽下限 3 格；余数分配给「溢出最大」的列。
- 垂直居中时多余行补在下方。
- 表头不强制居中，跟随列 `align`。
- 硬折仅在 `W < Σmin` 时启用，避免正常表格把英文单词切开。
- 不在本规格引入 ADR。
