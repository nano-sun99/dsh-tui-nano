## 3. 工具结果与退出事实

### 3.1 结果判定

主状态描述工具调用是否已经得到明确结论；退出事实描述进程的退出码、信号、超时或停止原因。缺少后者不等于前者未知。

1. 未收到终态结果时沿用 Pending / 既有中断生命周期，不从非空输出、任务开始、任务编号或无错误文字推断成功。
2. 官方结构化错误 `TOOL_OUTCOME_UNKNOWN` 保持“结果未确认”；`TOOL_NOT_STARTED` 保持既有中断含义；明确失败保持失败。
3. 保留既有真实终止事实判断：非零退出码、超时、signal、stopped 仍按既有失败或中断处理；`Code(0)` 不覆盖明确的结构化错误。
4. 对已收到官方明确成功结果、又无上述相反事实的调用，显示“完成”；Bash 缺少文本退出标记不得把成功降成未知。
5. 缺少明确结果结论、且没有可判定的终止事实时，仍显示“结果未确认”，不得以 `isError` 缺失代替显式 `false`。
6. 只使用同一调用的事实；实时、快照和恢复会话重放必须一致。孤立结果不关联到邻近调用。

### 3.2 用户可见反馈

- 明确成功：展示输出和“完成”；不显示“结果未确认”“工具未返回成功或失败结论”或“退出状态未返回”。空输出也可以成功，不伪造输出文字来证明成功。
- 明确失败或中断：展示真实失败 / 中断及已有原因；仅因数值退出码缺失，不再追加泛化的“退出状态未返回”警告。已有真实非零码、信号、超时和停止事实仍显示。
- 真正未知：保留“结果未确认”及“工具未返回成功或失败结论”；Bash 同时缺少终止事实时保留“退出状态未返回”。
- Pending：显示等待 / 执行中的既有反馈，不在结果尚未到达时预先渲染终止事实缺失警告。
- 退出码没有收到就保持未知 / 缺失，不能为隐藏警告写成 `0`；不改原始输出，不向持久会话补写猜测结果。
- 保留折叠、展开、行预算和颜色职责。通用工具的明确成功、失败和特殊未知错误继续按相同事实原则显示。

## 4. XHigh 扫光

1. 使用原设计的 1400ms 线性循环，周期不随终端列数或轨道宽度变长。
2. 深蓝底色及已填充比例不变；高光在填充区域从左向右移动，边缘以共享 Palette 的底色和高光色插值形成渐变，不只是一个纯色硬边块。
3. 从其他状态进入有效 XHigh，或重新打开并聚焦 XHigh 时，从左侧起播；普通重绘和同档持续停留不重新起播。选择后 200ms 内应出现可观察高光，不因上次相位等待数秒。
4. 一个完整循环内覆盖填充区左、中、右三个位置；循环拼接可以自然渐入渐出，不允许出现超过 200ms 的整条无高光空窗。
5. 只在模型面板可见、有效焦点是 XHigh、且未启用 reduced motion 时推进。关闭、遮挡、切换到非动效档位后不保持 XHigh 刷新。Max 沿用原有刷新规则。
6. `NANO_REDUCED_MOTION=1|true` 时保留静态底色、填充比例及标签，禁止高光移动。Low / High / 默认态 / Max、非匹配档位、官方档位集合及提交参数不改。
7. 100 / 60 列、dark / light 共四种组合都按同一规则工作；宽度极小也不越界、不除零、不使布局抖动。

## 8. 自定细节

- 主状态与数值退出事实分开；明确成功但没有退出码时，隐藏缺失警告而保留内部未知值，是本次推荐的展示细节，并非补造成功退出码。
- 不要求为所有空输出添加新文案；复用“完成”已足够，避免引入翻译和布局变化。
- 1400ms 取自已核对的设计 CSS；进入 200ms 及无高光空窗 200ms 是为可重复验收设定的上限，不声称来自设计原文。
- 高光宽度按填充区比例适配，具体插值曲线与 cell 取整由实施选择并记入测试；不新建颜色表或改变官方档位比例。
- 只在从其他状态进入有效 XHigh，或重新打开并聚焦 XHigh 时重置其相位；普通重绘与同档持续停留不重置。不借修复顺带改变 Max 的脉冲节奏（含相位）。
- 体量评估与结构选择：已向用户给出“不拆”与“拆成工具结果 / XHigh 两份”的真实候选及文档、执行单数量；用户于 2026-10-26 选择“不拆（推荐）”。保留 1 份规格、1 张执行 issue，一次交付两处无硬依赖的局部纠偏；没有需分别推进的实施里程碑，不把编码、测试、提 PR 当成额外阶段。
