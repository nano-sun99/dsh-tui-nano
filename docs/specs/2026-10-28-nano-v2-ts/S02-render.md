# [2026-10-28-nano-v2-ts/S02] 渲染内核

- 组标识：`2026-10-28-nano-v2-ts`；角色：子件 S02，单交付为一个能把视图模型稳定渲染成终端帧、并在真实长会话下不掉帧的渲染宿主。
- 状态：待合并，未实施。
- 总纲：[共享约定与依据](README.md)。上游：S01（生命周期与终端所有权）。下游：S03–S05。
- 合入前提：S01 的启动与终端独占可用；本份用夹具 + 真实会话双轨给出观感基线截图与帧时间实测。
- 发布由 S06 承担。

## 1. 边界

拥有 `src/render/`、`src/input/`、`src/theme/`。

提供：React 的终端 host config、cell 模型与写入、双缓冲与最小 diff、布局与换行、宽度计算（含 CJK / emoji / 组合字符）、主题令牌到颜色的映射、键盘与鼠标解码、焦点与事件分发、渲染预算与调度。

不实现：任何业务状态（对话、决策、终端、任务、调度、子代理都只提供视图模型）；不拥有会话地址与消息身份（S03）；不拥有键位表的业务含义（各功能声明，S02 只派发）。

S02 不保存业务事实。渲染层可以丢帧、可以裁剪视窗，但不能丢弃事件。

## 2. 渲染宿主

- 用 `react` + `react-reconciler` 自写 host config；布局复用 Yoga；不使用 Ink 的渲染 / 输出 / 输入层（选型理由见机制清单）。
- host config 的实例类型至少覆盖：根、块容器（垂直/水平）、文本（可换行、可样式的 run 序列）、定高区域、绝对定位覆盖层、原始 ANSI 透传区（用于图片协议与已确定不重排的内容）。
- 组件不直接写 stdout。所有输出经渲染队列，由单一写入器在帧边界一次性提交。
- 一帧 = 一次完整提交：计算 → diff → 生成字节 → 写 fd 1。禁止边算边写导致的半帧。

## 3. cell 模型与 diff

- 屏幕表示为 `{char, width, style, link}[]` 的二维 cell 缓冲，宽字符占两格、第二格为占位。
- 双缓冲：上一帧 vs 当前帧，只写变化的连续区间；行尾变化要能省略尾部空白。
- 样式用稀疏变更（SGR 只在变化时输出），单帧内样式切换次数要可测。
- 滚动是被识别的操作，不是全量重绘：整屏滚动优先用区域滚动序列。
- 帧输出必须可重放：同一视图模型 → 相同字节流（除时间戳类字段），以便截图基线与回归。

## 4. 布局

- 采用 Yoga 的 flexbox 引擎做「一次测量、一次放置」；只使用本产品用得到的子集：固定高度、内容高度、按比例分配、最小/最大、水平垂直堆叠、溢出裁剪、粘底滚动。
- 不使用浏览器级完整 flex；把这个子集在本份写死，避免各功能自行发明布局规则。
- 换行与裁剪按显示宽度而非码元数；CJK、emoji、ZWJ 序列、组合字符都要有测试。
- 布局结果对相同输入必须确定性，不允许依赖迭代顺序或对象键顺序。

## 5. 主题

- 颜色、间距、边框、强调等级来自令牌，不在组件里写裸值。
- 沿用现行 ADR：[独立 TUI 主题](../../decisions/2026-10-22-independent-tui-theme.md)、[主题范围](../../decisions/2026-10-22-nano-theme-scope.md)、[间距令牌架构](../../decisions/2026-10-26-spacing-token-architecture.md)。
- 深/浅两套；普通背景保留终端默认（不铺整屏实色），diff、选择、hover 等局部高亮用 Nano 自有 RGB。
- 令牌名与 v1 的语义层级对齐，便于把 v1 的视觉验收项直接搬过来；具体键名由本份实施时冻结并记录。

## 6. 输入解码

- 键盘：普通键、修饰键、组合键、多字节序列、kitty keyboard enhancement（终端支持时启用并降级）。
- 鼠标：点击、滚轮、拖拽选择、分栏拖拽；分片到达的 SGR 序列要能重组。
- 粘贴：bracketed paste 识别为批量输入而不是逐键事件。
- resize：合并为最后值（S01 已定），本份负责重排。
- 焦点：同一时刻只有一个焦点；覆盖层（问卷、审批、命令面板）优先于主体，Escape 逐层退出而不是一次关光。
- 输入解码产生的原始字节如无法识别，必须可诊断（限流记录），不能静默吞掉用户按键。

## 7. 渲染预算与长会话

- 目标：稳定输入下每帧可直接写出；高频流式到达时合并为有界批次，丢弃中间帧而不是排队。
- 虚拟化：视窗外的行不构建组件树；保留高度估算，滚动到未构建区域时按需构建。
- 有界缓存：宽度计算结果、样式解析结果、行高估算都要有上限，触顶后按 LRU 淘汰先进先出而不是无限增长。
- **明确不承诺**：本份不能消除 GC 停顿，也不能让渲染脱离 Node 事件循环。可承诺的是「渲染自身不产生无界增长」与「在给定实测基线内不掉帧」。超出基线的场景必须报告而不是声称达标。

## 8. 验收

1. 夹具渲染：一组覆盖宽字符、颜色、边框、覆盖层、滚动的固定夹具，输出字节流与截图基线一致（可重放）。
2. 观感基线：在真实 Ghostty、100 列，深/浅两套各截一组图，与 v1 已验收的同类界面逐项对比并记录差异。
3. 帧时间：1000 行 transcript 下滚动一屏、流式追加、窗口 resize 三类操作各给 p50/p95 实测数字，写入实施记录。
4. 长会话内存：持续追加至 5000 行后，内存增长有界（给出实测曲线），触顶后不继续增长。
5. 输入：中文输入法组合态、CJK 宽字符、emoji、粘贴、鼠标拖拽选择、分片 SGR 各有测试或人工验收记录。
6. 焦点：三层覆盖层下 Escape 逐层退出；覆盖层打开时主体不接收按键。

## 9. 机制清单

| 机制 | 解决什么 / 没有会怎样 | 确认与代价 |
| --- | --- | --- |
| `react-reconciler` 自写 host config | 用 React 的组件与生命周期，自己定终端语义；没有则要自造协调器 | 用户已批准选型；代价是须自己保证调度与虚拟化 |
| 单一写入器 + 帧边界提交 | 避免半帧与交错写；没有则屏幕随机撕裂 | 本次新增 |
| cell 双缓冲 + 最小 diff | 长会话全量重绘不可接受 | 本次新增 |
| Yoga 布局子集（写死） | 复用成熟 flexbox，避免自写布局引擎；没有则 S02 要自造布局 | 用户 2026-10-28 选择；代价是引入 Yoga 依赖与布局语义边界 |
| 虚拟化 + 有界缓存 | 长会话内存与帧时间；没有则越用越卡 | 本次新增；代价是滚动到未构建区有构建延迟 |
| 输入解码与焦点栈 | 覆盖层与主体的按键归属 | 本次新增 |
| 可重放帧输出 | 截图基线要能回归，否则视觉改动无法验收 | 本次新增 |

## 10. 自定细节

- 组件 API 的具体形态（`<Box>`、`<Text>`、`<Overlay>` 等命名与 props）由本份实施时定义并冻结，功能子件只消费。
- `react` / `react-reconciler` 版本在实施时选定并写入 README；不在规格里写死。
- Yoga 的加载方式（WASM，无平台二进制）与版本在实施时选定并记录；布局子集以本 §4 为准。
- 虚拟化窗口大小、缓存上限、批次大小由实测确定。
- 是否启用备用屏幕由 S01 与 S06 共同决定；本份按「已决定」的方式适配，不自行切换。
- 图片协议（Kitty / Sixel）不在本份范围；如后续需要，作为原始透传区的一种，另立需求。
