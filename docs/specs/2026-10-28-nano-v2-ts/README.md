## 1. 目标与完成含义

在不重写 Agent 内核的前提下，把 nano 从「Rust 窗口进程 + Node 宿主进程 + 自造跨进程协议」迁移为「单一 Node 进程内的官方 profile 插件，UI 同进程直接渲染」。

完成是有限承诺：本组 6 份子件各自的约定功能、正常/异常/边界/回归测试通过，真实终端证据齐全，`inspect` 类检查与文档检查为绿，且没有未处理的已知阻断缺陷。**不承诺**一次迁移即达到 v1 已验收的全部行为；逐条承接情况登记在 §8，未承接项必须显式标注而不是静默丢弃。

不接受这些替代交付：用假数据冒充流式、用静态截图冒充终端渲染、用单进程声称「性能更好」而没有当次实测、用删除验收项冒充「行为一致」。

## 2. 已确认决定

| 决定 | 本轮确认内容 | 影响 |
| --- | --- | --- |
| 实现语言 | TypeScript（ADR 见上） | Rust 61,395 行、15 个 crate、789 个测试退出主线 |

| 内核归属 | 官方 DSH 独占 Agent/模型/工具/会话/权限/持久化 | nano 不重写内核，只消费公开导出 |
| 行为权威 | v1 规格冻结，行为语义照旧 | 本组只改实现语言与运行形态 |

| 数据根 | 沿用 `~/.dsh-tui-nano`；官方会话存储不动 | v1 未发布，不承诺数据迁移 |

「把自建组合根（app with own entry）一起做掉」已被否决：它会让本次同时承担「换语言」和「换宿主」两件事，且后者是另一个可独立决策的问题（C1 vendor 自持）。本次只换语言与进程模型。

## 3. 不做什么

- 不重写 Agent 内核、模型适配、工具执行、沙箱、会话格式或权限模型。
- 不引入 MCP 管理、检查点回滚、多后端内核切换（Claude / Codex 等）、插件市场、远程宿主、跨机器所有权。
- 不改官方凭据、全局指令、`storages/`；不复制官方凭据。
- 不做 Rust 与 TypeScript 双实现并存，不做「先并行一段时间再切」。
- 不在本组引入新的视觉体系；沿用 ADR [`2026-10-22-nano-theme-scope`](../../decisions/2026-10-22-nano-theme-scope.md)、[`2026-10-26-spacing-token-architecture`](../../decisions/2026-10-26-spacing-token-architecture.md)、[`2026-10-22-independent-tui-theme`](../../decisions/2026-10-22-independent-tui-theme.md)。

## 4. 运行结构与责任

```text
Ghostty
  └─ dsh --profile dsh-tui-nano（一个 Node 进程）
       ├─ 官方 DSH：Agent / 模型 / 工具 / 会话 / 权限 / 持久化
       └─ nano 插件（同进程）
            ├─ 渲染宿主：react-reconciler 自写 host config → cell → ANSI
            ├─ 输入层：raw mode 解码、键位、补全
            └─ 各功能宿主：会话 / 决策 / 终端 / 任务 / 调度 / 子代理
```

一个窗口一个 Node 进程。多个窗口可在同仓不同 worktree 或同一 checkout 的不同会话工作；文件冲突仍靠 worktree 隔离。

**不存在的东西**（与 v1 的差别）：Rust 窗口进程、`protocol/nano-protocol.json` 的线上契约、`bridge/runtime/frames|transport|writer` 的帧与有界写、`crates/nano-runtime` 的进程管理与生命周期、启动前的 `dsh --version` 预检、启动后的二次复检。

### 4.1 所有权

| 对象 | 所有者 | nano 只保留 |
| --- | --- | --- |
| 会话、消息、工具结果 | 官方 session 与持久化 | 可丢弃的展示缓存、阅读锚点 |
| 模型、推理强度、权限 | 官方选择与预设服务 | 当前值的展示、正在提交的请求 |
| 主会话输入 | 官方收件箱与回执 | 未发送草稿、待确认状态 |
| 子代理身份与续聊 | 官方 catalog 与控制接口 | 导航栈、子草稿 |
| Shell / jobs / PTY / 调度 | 官方执行、任务、终端、schedule 服务 | 视窗、游标、表单草稿 |
| 终端屏幕与光标 | nano（本进程独占 fd 0/1） | —— |

**终端所有权是本次最关键的边界**：进程启动后由 nano 独占 raw mode、resize 信号与 fd 0/1；官方侧不得另行写入 stdout（stdout 一旦被官方日志污染，屏幕即损坏）。S01 必须给出可核证据。

### 4.2 数据边界

数据根 `~/.dsh-tui-nano` 沿用；官方会话存储与凭据仍由 `$DSH_HOME` 解析。会话挂载账本（`.dsh-tui-nano/session-mounts.json` + `.lock`）与调度租约（`schedule.lock`）语义照 v1 S01 §2.1 与 S11 执行，只把「宿主 pid」从 Node 子进程 pid 改为本进程 pid。

跨会话内容隔离仍是硬约束，沿用 v1 总纲 §4.2 全部条款。

## 5. 故障与安全共同规则

沿用 v1 总纲 §5 的 10 条，仅作两处必要替换：

1. **第 5 条（退出）**改为：退出先停渲染与新增工作，再停监听、命令与 PTY，取消 Agent/子代理并排空持久化，恢复终端属性与光标，最后退出进程。任一步失败逐项报告，不静默成功。
2. **第 6 条（异常退出）**改为：进程崩溃或强杀时终端属性可能残留，必须提供可复制的恢复提示（`reset` 或等价），并说明这是 OS 层能力缺口，不承诺所有场景必无残留。

新增第 11 条：**渲染异常不得吞掉业务事实**。渲染层抛错要落到可见错误提示并保留数据；不允许因为一棵子树渲染失败而导致消息、审批或队列消失。

## 9. 机制清单

| 机制 | 解决什么 / 没有会怎样 | 确认与代价 |
| --- | --- | --- |
| 进程内插件渲染 | 取消跨进程协议与帧层；没有则继续维护一套 3,459 行自造契约 | 用户 2026-10-28 拍板；代价是失去崩溃隔离 |
| `react-reconciler` 自写 host config | 用 React 的树与生命周期，自己定终端 cell 语义；没有则要自造协调器 | 用户已批准选型；代价是须自己保证调度与虚拟化 |
| Yoga 布局子集 | 复用成熟 flexbox，避免自写布局引擎；没有则 S02 工程量最大 | 用户 2026-10-28 选择；代价是引入 WASM 依赖，布局只用写死的子集 |
| 终端独占契约 | 官方日志污染 stdout 会导致整屏损坏；没有则偶发不可复现的花屏 | 本次新增；须有可核证据，属 D01 |
| 会话挂载账本（pid 换为本进程） | 两个窗口驱动同一根会话仍会互相破坏；没有则静默双写 | 沿用 v1 S01 §2.1；pid 语义改变 |
| 调度租约 | 一个根会话只能有一个 scheduler | 沿用 v1 S11；不改 |
| Rust 资产归档制 | 不并存第二套实现，同时保留历史可查 | 用户 2026-10-28 拍板（tag + 归档分支） |
| 行为承接对账表 | 防止「换语言」被用作丢功能的借口 | 本次新增；§8.2 |

## 10. 自定细节

- 目录结构 `src/boot|runtime|render|input|theme|conversation|transcript|decisions|attachments|sessions|controls|skills|terminal|jobs|monitor|schedule|subagents` 按子件归属，由本总纲一次性定，子件不另行命名。

- 渲染帧率、虚拟化窗口大小、预览合并窗口等数值由对应子件按实测定，不在规格里先写死。
- v1 规格 README 头部加的那行指向由本组 PR 一并提交；其余 v1 正文不动。
