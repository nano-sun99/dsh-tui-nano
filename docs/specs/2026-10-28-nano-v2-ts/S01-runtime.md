# [2026-10-28-nano-v2-ts/S01] 运行时与启动

- 组标识：`2026-10-28-nano-v2-ts`；角色：子件 S01，单交付为一个能在真实终端里启动、独占终端、正常退出的单进程 Nano 骨架。
- 状态：待合并，未实施。
- 总纲：[共享约定与依据](README.md)。上游：无。下游：S02–S06。
- 合入前提：用真实官方 profile 完成「启动 → 首帧 → 空闲 → 正常退出 → 再启动」闭环；`stdout` 无官方写入有可核证据；`dsh plugin` 安装与卸载双向通过。
- 发布由 S06 承担。

## 1. 边界

拥有 `package.json`、`bin/`、`src/boot/`、`src/runtime/`。

提供：进程入口、官方 profile 的安装与卸载、启动顺序、能力快照与版本判定、终端所有权（raw mode / resize / fd 0/1）、有序关停、会话挂载账本、数据根解析、错误归一化。

不实现：渲染与布局（S02）、对话与阅读（S03）、输入增强与会话管理（S04）、终端/任务/调度/子代理业务（S05）、打包与发布验收（S06）。

S01 不拥有任何业务语义。它在渲染层就绪前也必须能让进程健康存活与退出（否则无法验证生命周期）。

## 2. 启动顺序

1. 解析实际路径：Node、`dsh` 可执行、本包目录、绝对工作目录、数据根、目标会话。不通过用户 shell 拼接参数。
2. 校验能力快照（§4）。不成立即报明确失败并给出修复路径，不降级启动。
3. 启动官方 `dsh --profile dsh-tui-nano --patch <runtime-patch>`，由官方加载本包插件。
4. 插件获得控制权后第一时间接管终端：进入 raw mode、订阅 resize、确认 fd 0/1 归属（§3）。
5. 取得根会话认领（§5），失败即退出，不创建会话、不挂调度、不发模型请求。
6. 创建或恢复主会话；确认官方写锁；失败保留草稿并报错，不静默换会话。
7. 渲染宿主就绪后绘制首帧；首帧必须先于会话内容加载完成，避免空白等待。
8. 首帧可见后才允许接受用户动作。

**首帧优先是硬约束**：从进程启动到首帧可见的这段时间里，不得等待模型、网络或会话列表。

## 3. 终端所有权

- 进入 raw mode 后，nano 是 fd 0/1 的唯一写入者。
- 必须证明官方侧不写 stdout：启动全程捕获 stdout，任何非 nano 写入都记为失败；如官方默认组合存在 stdout 日志，须在 patch 中关闭，而不是靠用户运气。
- 诊断信息一律写 stderr 或文件，绝不进 stdout。
- 退出、异常、SIGINT/SIGTERM/SIGHUP 都必须在路径上恢复终端属性（raw mode、光标可见性、备用屏幕、鼠标上报）。
- 强杀与断电不承诺恢复；须在首次启动与 `--help` 中给出可复制的恢复提示。
- resize 采用最后值合并，不排无限队列；同一帧内多次 resize 只触发一次重排。

## 4. 能力快照与版本判定

沿用 v1 的「能力三态」思路：以必需能力是否全部 `supported` 作为启动门槛，而不是以版本号相等作为唯一判据。

- 能力清单至少覆盖：会话控制、用户问题、审批、附件准入、调度、终端控制、任务观察、子代理目录、模型选择、权限预设。
- 版本号仍记录并展示，但只在能力快照不可判定时才作为硬门槛。
- 任一必需能力 `unavailable` 或 `unsupported`：启动失败，输出缺失能力名与已知的修复路径（升级官方、切换 profile、装插件）。
- 允许「部分能力不可用但非必需」（如调度）时，相关入口显示为不可用而不是崩溃。
- 官方升级后行为漂移但能力名不变的风险**不由本机制兜底**——本份只保证「能力缺失能被发现」，不宣称能发现语义漂移。

## 5. 会话挂载账本

沿用 v1 S01 §2.1 全部规则（`wx` 原子建锁、token fencing、`pid` 存活判定、提交前回读、损坏即拒绝启动、活 pid 不回收），只作一处替换：

- 账本中记录的 `pid` 由「Node 宿主子进程 pid」改为**本进程 pid**（`process.pid`）。
- 其余字段、阈值（30 秒 stale 门槛、0700/0600 权限）与释放时机不变。
- 同机第二个窗口驱动同一根会话时报「被 pid X 占用」，保留草稿，不删锁、不接管、不改建新会话。

S01 必须证明：认领在激活主会话期间确实持有；认领失败时调度尚未运行；两个不同根会话的 runtime data 互不可见。

## 6. 关停顺序

固定顺序，任一步失败继续后续步骤并逐项报告：

1. 停止接受新动作，UI 进入退出态。
2. 取消在飞的模型请求与子代理，保留队列（不静默清空用户输入）。
3. 停止监听（文件/事件订阅）。
4. 释放本窗口拥有的 PTY 与终端会话。
5. 排空持久化，等待官方写完成。
6. 释放在飞认领与租约。
7. 恢复终端属性，写最后一段诊断。
8. 退出进程。

全局预算由本份定义并记录；超时后强制结束但仍在 stderr 报告未完成项。SIGINT/SIGTERM/SIGHUP 走同一条路径；重复信号允许提前终止，但不得早于第 7 步。

## 7. profile 安装与卸载

- 首次启动自动安装 `dsh-tui-nano` profile；安装失败给可复制的手工命令，不静默降级。
- 卸载必须删除本包写入 profile 的全部行（含 `cordis.patch.yml` 中的 patch 行），不残留。
- 安装与卸载都不得修改用户的全局指令、凭据或 `$DSH_HOME/storages/`。
- 安装过程中产生的临时目录与锁要可回收；失败安装留下的半成品须能被子序列启动识别并修复或明确报告。

## 8. 失败分类与不变量

| 类 | 例 | 处理 |
| --- | --- | --- |
| 不可继续 | 能力缺失、认领被占、profile 安装失败 | 启动前失败，明确原因与修复路径，不动会话 |
| 可降级 | 调度不可用、附件能力不可用 | 启动成功，入口标不可用，不崩 |
| 内部错误 | 渲染层抛错、工具调用异常 | 可见错误 + 保留数据；不允许吞掉业务事实 |

不变量：任何时刻只有一个窗口持有某根会话的认领；任何时刻只有一个进程写 fd 0/1；关停路径不丢用户已输入未提交的草稿。

## 9. 验收

1. 真实官方 profile 冷启动到首帧可见 ≤ 可接受阈值（实施时实测并记录基线），且首帧不等模型。
2. 启动全程 stdout 无官方写入（捕获证据）。
3. 正常退出、SIGINT、SIGTERM、SIGHUP 四条路径后终端属性完全恢复（raw mode / 光标 / 备用屏幕 / 鼠标上报逐项核对）。
4. 强杀后用 `reset` 可恢复；恢复提示可在 `--help` 与首次启动读到。
5. 能力快照：构造一个缺失必需能力的组合，启动必须失败并点名缺失能力。
6. 挂载账本：同机双窗口争同一根会话，第二个窗口被拒且草稿保留；不同根会话互不可见。
7. `dsh plugin` 安装 → 启动 → 卸载 → 再安装，全链路无残留。
8. 关停预算超时场景：强杀后 stderr 列出未完成步骤。

## 10. 机制清单

| 机制 | 解决什么 / 没有会怎样 | 确认与代价 |
| --- | --- | --- |
| 进程内插件入口 | 消除第二进程与自造协议；没有则本次迁移不成立 | 用户 2026-10-28 拍板；代价是无崩溃隔离 |
| 终端独占 + stdout 净化证据 | 官方日志污染 stdout 会毁整屏；没有则花屏不可复现 | 本次新增；须实测，属最高优先 |
| 能力快照替代版本硬等 | 官方 rc 期版本频繁变动，硬等会让升级即死 | 沿用 v1 思路并扩展为启动门槛；不宣称能发现语义漂移 |
| 挂载账本（pid 改为本进程） | 同根会话双写会互相破坏 | 沿用 v1 S01 §2.1；pid 语义改变 |
| 首帧优先 | 启动体验；没有则用户面对空白等待 | 本次新增 |
| 八步有序关停 | 终端残留、认领泄漏、草稿丢失 | 沿用 v1 结构并合并双进程步骤 |

## 11. 自定细节

- `bin/` 内只做参数解析与转发，不含业务；业务从 `src/boot/` 起。
- 数据根默认 `~/.dsh-tui-nano`，可显式指定绝对路径；解析规则与 v1 一致。
- 能力快照的具体能力名以官方导出为准，实施时冻结并写入 README；不在规格里先臆造名字。
- 关停预算的秒数由实施时按真实官方行为实测确定，写入本份实施记录。
- 错误码沿用 v1 的分类意图（不可继续 / 可降级 / 内部错误），不保留 `nano/*` 线上错误码格式。
- profile patch 文件位置由本份决定；S06 打包时引用同一份，不另建第二份。
