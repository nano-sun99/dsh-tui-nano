# [2026-10-28-nano-v2-ts/S04] 输入与会话控制

- 组标识：`2026-10-28-nano-v2-ts`；角色：子件 S04，单交付为一个输入完整、会话可控、模型与权限可切换的可用产品面。
- 状态：待合并，未实施。
- 总纲：[共享约定与依据](README.md)。上游：S02（渲染与输入）、S03（对话与场景）。下游：无。
- 合入前提：S03 的会话地址、消息身份与场景注册冻结；本份用真实官方服务完成附件提交、会话恢复、压缩与权限切换验证。
- 发布由 S06 承担。

## 1. 边界

拥有 `src/attachments/`、`src/sessions/`、`src/controls/`、`src/skills/`。

提供：多行输入与内容顺序、`@` 文件引用、图片与通用文件附件、补全（文件/命令/技能）、命令面板、会话列表与恢复、会话改名、上下文占用展示、上下文压缩、模型与推理强度选择、权限预设切换、技能目录与项目规矩来源展示。

不实现：对话与 transcript（S03）、终端与后台任务（S05）、Agent 内核行为。

## 2. 输入与内容顺序

- 输入内容是一个有序列表（文本段 + 附件段），保持用户排列顺序；预览与提交顺序必须一致。
- 多行输入、换行、历史回溯、撤销重做在输入框内自洽；提交失败恢复原文与附件。
- `@` 引用只插入路径候选，**不读取文件内容**（沿用 v1 边界，README 必须写清这一点，避免用户误以为已读入）。
- 引用路径随会话工作目录变化；工作目录被 Agent 移动后，新引用按新目录解析，已有卡片按渲染时的目录解析。
- 草稿按会话地址保存在内存，不跨进程恢复，不写入官方存储。

## 3. 附件

- 图片：暂存 → 校验 → 规范化 → 持久化 → 得到可提交引用；尺寸、格式、动画转换受官方准入策略约束，超限明确拒绝并说明原因，不静默降级。
- 通用文件：按原字节保存并生成文件引用；提交时校验归属。
- 回执一次性：已提交未退休的回执不得再次提交；提交成功或失败都要有明确终态。
- 附件数量与总字节上限同时生效，按来源顺序计数。
- 调整通知要报告实际存储的尺寸与格式；必须转换才能存的情况如果无法转换，**拒绝而不是丢帧**。

## 4. 补全与命令面板

- 补全来源：文件路径、`/` 命令、技能命令。三类结果在同一列表里要可区分，不混排成同一种。
- `Tab` 补全填入不执行；`Enter` 执行明确写下的内容。示例文本可展示但不可被误插入。
- 命令面板是纯检索与转发，不自造命令语义；可用命令目录来自官方服务，本份不维护第二份清单。
- 补全结果为空的场景要显示「无匹配」而不是空白。

## 5. 会话列表与恢复

- 列表来自官方会话查询，不解析、不改写官方存储文件。
- 恢复会话要有明确的重启/挂载语义：切到新根会话前必须释放旧根会话的认领与租约，不能留下旧会话偷偷运行。
- 冷会话改名要先取得写权限；拿不到就明确拒绝，不静默失败。
- 会话列表在读取或加载失败时区分「加载中」「读取失败」，不把错误显示成空列表。
- 子代理会话、fork 祖先、空日志不进入普通会话计数（沿用 v1 口径）。

## 6. 上下文与压缩

- 上下文占用展示官方投影值，标注是投影而非精确计费；计费用量与投影分开显示，不混为一个数。
- 压缩走官方行为，本份只转发并按官方稳定文本呈现结果；压缩过程中可取消，取消结果如实显示。
- 压缩历史与阶段提示在窄宽度下要能降级成单行，不能挤成一团。

## 7. 模型、推理强度与权限

- 模型目录来自官方服务；切换走官方选择路径，不直接改写配置。
- 推理强度只展示当前模型声明的档位；不可用的档位显示为不可选并说明原因。
- 权限预设只展示官方提供的预设；切换走官方切换路径，不自行拼装策略。
- 权限变更必须有可见的当前状态，用户在任何时刻都能回答「我现在是什么权限」。
- 切换失败保留原值并显示失败原因，不显示成已切换。

## 8. 技能与规矩来源

- 技能目录只读官方快照，附上官方命令名；预览按官方路径有界只读。
- 项目规矩只展示官方折合后的来源、时间与预算提示，不自行解析指令文件。
- 不写自动记忆；不把技能目录当成插件市场。

## 9. 验收

1. 有序输入：文本 + 一张图片 + 一个文件混合排列，提交后顺序与预览一致。
2. 附件：超限拒绝、动画无法转换时拒绝、回执重复提交被拒，三条各一条证据。
3. `@` 引用：工作目录被移动后，新引用按新目录解析（真实 Agent 移动会话目录场景）。
4. 补全：文件、命令、技能三类各一条；空结果提示一条。
5. 会话：列表 → 恢复 → 改名 → 再恢复，全程认领与租约正确释放。
6. 压缩：正常压缩、压缩中取消、压缩后上下文数字变化，三条各一条。
7. 模型与权限：切换成功、切换到不可用项被拒、切换失败保留原值，三条各一条。

## 10. 机制清单

| 机制 | 解决什么 / 没有会怎样 | 确认与代价 |
| --- | --- | --- |
| 有序输入内容列表 | 文本与附件保持用户顺序；没有则预览与提交不一致 | 沿用 v1 S02 形状 |
| 附件回执一次性 | 重复提交会导致重复落盘或错乱 | 沿用 v1 S06 语义 |
| `@` 只插路径不读内容 | 边界清晰；否则用户会误以为模型已看到文件 | 沿用 v1 边界，须在 README 明示 |
| 会话切换先释放认领 | 两个根会话同时活着会互相破坏 | 承接 S01 账本机制 |
| 投影与计费分开显示 | 两个数混在一起会被当成精确值 | 沿用 v1 S07 口径 |
| 权限状态始终可见 | 用户必须随时知道当前授权范围 | 本次强化为硬要求 |

## 11. 自定细节

- 输入框内部状态机（撤销重做深度、历史条数）由本份定义并实测记录。
- 附件数量上限、单文件字节上限以官方准入策略为准，本份只记录测得的实际值。
- 补全候选条数、去抖间隔由实测确定。
- 上下文条的颜色分档沿用 ADR `2026-10-26-spacing-token-architecture` 与 v1 视觉验收，不重新定义。
- 模型与权限选择器的具体形态（列表/面板/命令行）由本份决定，键位由 S06 冻结。
