# [2026-10-28-nano-v2-ts/S05] 终端、任务与后台

- 组标识：`2026-10-28-nano-v2-ts`；角色：子件 S05，单交付为把官方终端、任务、监听、调度与子代理全部接进同一界面的重活面。
- 状态：待合并，未实施。
- 总纲：[共享约定与依据](README.md)。上游：S03（场景、transcript、决策入口）。下游：无。
- 合入前提：S03 的展示槽位与只读接口冻结；每一项都用真实官方服务验证，不允许用命令输出框冒充终端、用日志滚屏冒充任务面板。
- 发布由 S06 承担。

## 1. 边界

拥有 `src/terminal/`、`src/jobs/`、`src/monitor/`、`src/schedule/`、`src/subagents/`。

提供：内嵌 PTY 终端、任务面板、Monitor 监听与投递、定时任务管理、子代理导航与续聊。

不实现：Agent 内核、进程执行器、Cron 引擎、第二份任务表、第二份队列。

## 2. 内嵌终端

- 真实 PTY，经官方终端控制服务创建、附着、保留、释放、重命名、关闭；本份不自建 PTY 管理。
- 输入与缩放按附着本地序列校验；越序或失配的输入要丢弃并报告，不能盲写进 PTY。
- 输出背压：消费端慢时降级为有界缓冲并标记丢弃区间，不无界排队吃内存。
- 终端保留子程序自己的显式颜色，不做全屏改色；与本产品主题共存但不互相覆盖。
- 关闭、切场景、退出程序都要释放 PTY；强杀不承诺清理，须在文档写明。
- 本份不注册任何 Agent 工具，终端只服务用户。

## 3. 任务面板

- 任务是官方 `jobs` 的只读观察层：不维护第二份任务表，不另挂 controller，不自己发完成通知。
- 输出按绝对偏移非消费读取；查看任务输出不得推进别人（含模型）的消费游标。
- 停止只回答「已请求停止」或「已结束」；不存在的任务明确报不存在，其余取消异常保持内部错误。
- 任务行显示：名称、状态、所属调用、耗时、可展开输出；长输出有界裁剪并标注。
- 人工命令（`!` 前缀）以用户权限执行，输出作为合成上下文注入但不唤醒模型；首次使用必须提示「这是你的系统权限，不是 Agent 授权」。

## 4. Monitor

- 监听采用有界预算：单条通知与批量的字节/令牌上限都要有，触顶裁剪并标注，不静默丢。
- 通知合并按时间窗与预算双约束；合并结果要能追溯是哪几次输出。
- 投递分两档：`notify` 会**唤醒模型并产生费用**，`quiet` 不唤醒。默认必须是 `quiet`，切到 `notify` 要有明确告知与开关。
- 外部日志与 Monitor 事件**不能冒充用户授权**；不能因为收到某段输出就扩大权限或重置自动唤醒预算。
- 一个任务只有一个通知渠道所有者；本份不与官方通知竞争。

## 5. 定时任务

- 复用官方调度服务与存储；不自写 Cron，不自己计时重复派发。
- 一个根会话一个 scheduler，靠租约保证；租约拿不到就不挂调度并报 `unsupported`，不静默降级。
- 官方无暂停/恢复接口，**停止只能删除**；UI 必须如实呈现这一点，不得提供假的「暂停」。
- 投递非严格一次，可能重复；补投只补最近一次，过期的一次性任务仍尝试投递。这些语义要在界面上可读。
- 子代理不能使用调度工具。

## 6. 子代理

- 目录与成员来自官方会话目录；活动状态来自官方 live 注册表；时间来自子会话投影。
- 续聊只走官方子代理提示接口（排队或插话），打断只用「由父代理打断」，**绝不使用销毁语义**。
- 结束事件的停止原因原样呈现，未知原因标为未知，不猜测归类。
- 子地址的实时订阅必须授权并回放子会话日志；父/兄弟内容不得进入该订阅。
- 容量拒绝、客户端取消两类失败要与一般错误区分显示。
- 导航栈与子草稿按地址保存；返回父会话不丢父草稿。

## 7. 跨功能不变量

- 跨会话内容隔离依旧成立：终端、任务输出、Monitor 通知、调度记录、子代理内容都不跨地址出现。
- 所有有界缓冲触顶都必须可见标注（裁剪位置 + 完整内容位置），不允许静默截断。
- 所有涉及费用或授权的动作（`notify` 唤醒、权限变更、调度删除）都要二段确认或明确提示。

## 8. 验收

1. 真实 PTY：创建 → 运行一个交互程序 → 缩放 → 切场景再回来 → 关闭，全程可用；越序输入被拒。
2. 背压：快速产生大量输出时，界面不卡死、丢弃区间有标注。
3. 任务：启动后台任务 → 面板看到 → 展开输出 → 停止；查看输出不影响模型消费游标。
4. 人工命令：`!` 执行的输出进入上下文但不唤醒模型；首次提示出现。
5. Monitor：`quiet` 不唤醒；`notify` 唤醒并产生费用（用可控场景验证一次）；超预算裁剪有标注。
6. 调度：创建 → 触发 → 删除；租约被占时不挂调度并报 unsupported；UI 无假「暂停」。
7. 子代理：进入子对话 → 续聊 → 打断 → 返回父会话；子内容不出现在父 transcript；容量拒绝与取消各一条。

## 9. 机制清单

| 机制 | 解决什么 / 没有会怎样 | 确认与代价 |
| --- | --- | --- |
| 官方 PTY 而非自建 | 终端语义（序列、缩放、屏幕恢复）极难自造 | 沿用 v1 S09；本份只做前端 |
| 序列校验与本地 ack | 防止乱序输入打乱交互程序 | 沿用 v1 S09 |
| 只读任务观察 + 非消费读取 | 维护第二份任务表会漂移；消费游标被抢会吞掉模型可见输出 | 沿用 v1 S08/S10 |
| 通知预算与合并 | 无界通知会撑爆上下文与内存 | 沿用 v1 S10 |
| `notify` 默认关闭 | 唤醒会产生费用，必须用户显式选择 | 本次强化为默认 `quiet` |
| 调度租约 | 一个根会话一个 scheduler | 沿用 v1 S11 |
| 子代理只用父代理打断 | 销毁会破坏会话与持久化 | 沿用 v1 S12 |
| 地址级订阅授权 | 防止父子内容串台 | 沿用 v1 S12 |
