## 1. 边界

拥有 `packaging/`、`tests/e2e/`、`docs/release/`、`README.md`、`README.en.md`、键位表与验收证据目录。

提供：npm 包结构、安装与卸载脚本、键位表冻结、跨功能 e2e、发布验收矩阵、证据归档、Rust 资产退场、文档更新。

不实现任何业务功能。发现功能缺失时报告并退回对应子件，不在本份补齐。

## 2. 包结构与分发

- 单一 npm 包，`bin` 暴露 `nano`（沿用命令名）。
- 依赖官方包使用明确的版本区间；升级策略写入 README（跟随、锁定、还是窗口）。
- 不引入平台相关二进制（本次迁移的收益之一）；如将来需要，走独立需求。
- 包内容不含测试夹具、证据截图与开发脚本。
- 安装路径与数据根的关系写进 README；卸载说明可复制、可执行。

## 3. 安装与卸载

- 首次启动自动安装 profile；失败给手工命令。
- 卸载必须可逆：删净 profile 中的本产品行，保留用户自己的配置与凭据。
- 升级路径明确：版本不兼容时报明确原因，不静默降级、不猜字段。
- 三向验证：全新安装、升级安装、卸载后重装，各一条证据。

## 4. 键位表冻结

- 汇总各子件声明的键位，输出一张完整表并冻结；后续改动必须走修订。
- 检查冲突：全局快捷键与输入态、覆盖层、终端面板之间不得抢占。
- 在 `--help` 与 README 中提供同一份表，不出现两处不一致。

## 5. 发布验收矩阵

| 维度 | 必测 |
| --- | --- |
| 环境 | macOS arm64 + Ghostty 全屏；记录未验证环境并明确不宣称 |
| 启动 | 冷启动首帧、二次启动、resume 启动 |
| 主链路 | 对话 → 工具 → 差异 → 审批 → 完成 |
| 长会话 | 连续多轮后滚动、内存、帧时间 |
| 异常 | 断网、官方进程异常、强杀后恢复、终端属性残留 |
| 安全 | 审批无答即拒、`notify` 默认关闭、人工命令权限提示 |
| 跨会话 | 主/子地址内容隔离逐项 |

未填满的维度要在发布证据里显式标注为未验证，不得用「应该没问题」代替。

## 6. 证据与文档

- 每项验收产出可核证据（截图、命令输出、帧时间数字），放在 `docs/release/<version>/`。
- README 重写：定位、能力、边界、环境要求、安装、键位、已知限制、与官方的版本关系。
- 已知限制必须包含：无崩溃隔离、共享事件循环的性能上限、强杀后终端可能残留、调度无暂停、投递非严格一次、`notify` 计费。
- v1 规格头部加一行指向本组，标明 S01 已被取代、其余行为继续有效；v1 正文不动。

## 7. Rust 资产退场

顺序固定：

1. 在 `main` 上打 tag `rust-final`，推分支 `archive/rust-v1` 指向同一提交。
2. 删除 `crates/`、`Cargo.toml`、`Cargo.lock`、`rust-toolchain.toml`。
3. 删除 `protocol/`（跨进程契约）；`bridge/` 下已被各子件吸收的业务代码逐目录移除，不整目录保留。
4. 清理根 `AGENTS.md` 中仅对 Rust 生效的构建与测试说明，指向新的开发命令。
5. `docs/specs/2026-10-20-nano-v1/` **保留不删**，作为行为权威与历史。
6. 在 README 记录 `rust-final` 的位置，供追溯。

任一步不可逆前先确认 tag 与归档分支已推到远端。

## 8. 验收

1. 三向安装验证（全新 / 升级 / 卸载后重装）通过。
2. 键位表冻结且与 `--help` 一致。
3. 发布矩阵各维度有证据；未验证项已标注。
4. 已知限制清单完整，且与实际行为一致（逐条核对）。
5. Rust 资产退场后：主分支上无 Rust 构建产物、无跨进程协议、`npm install` 后可直接启动。
6. 文档检查为绿。
7. 卸载后用户配置与凭据未被修改（对比前后快照）。
