# [2026-10-28-nano-v2-ts/S03] 对话与阅读决策

- 组标识：`2026-10-28-nano-v2-ts`；角色：子件 S03，单交付为一个能真实对话、能读懂 Agent 在做什么、能处理审批与问卷的完整交互面。
- 状态：待合并，未实施。
- 总纲：[共享约定与依据](README.md)。上游：S01（生命周期）、S02（渲染宿主）。下游：S04、S05。
- 合入前提：S02 的 host config 与输入 API 冻结；本份用真实官方会话完成发送、流式、工具调用、差异、审批与问卷验证。
- 发布由 S06 承担。

## 1. 边界

拥有 `src/conversation/`、`src/transcript/`、`src/decisions/`。

提供：会话地址与草稿、提交与队列（queue / steer）、停止与清空、消息身份映射、流式预览与持久消息合并、transcript 只读渲染接口、markdown 渲染、工具卡、文件差异卡、问卷与审批的完整交互、场景与功能注册。

不实现：附件与引用（S04）、会话列表与压缩（S04）、模型与权限切换（S04）、终端/任务/调度/子代理（S05）。

S03 不保存第二份会话历史。消息、工具结果、队列与中断事实都以官方会话记录为准；本份只保留可丢弃的展示缓存、未发送草稿与阅读锚点。

## 2. 会话地址与消息身份

- 地址区分主会话与子会话；草稿、队列、阅读锚点、决策卡片都按地址隔离。
- 用户消息主键用官方 `user/message.seq`；`source.rpcId` 只在 `user-rpc` 源上存在，不能当作通用主键。
- 工具调用用 `callId`，工具结果用 V4 顶层 `toolCallId`；二者不可互换。
- 本地回显只用于「点了就看见」，不写入历史、不参与去重以外的判定；重连即失效。
- 会话重用返回不同 ID、工作目录冲突、写锁被占都属于失败，不得静默改成另一个会话。

## 3. 输入提交、队列与停止

- 提交上限与 v1 一致（单次 32 KiB 量级，具体数值由本份实测后记录），超限明确拒绝并保留原文。
- 运行中默认**排队**；显式**插话**走 steer，且明确标注是尽力而为、可能不生效。
- 停止生成不删除已排队内容（官方 cancel 语义固定保留收件箱）；「停止并清空」是逐项删除 + cancel 的复合动作，部分失败要报告剩余项，不得宣称已清空。
- 编辑带附件的队列项一律禁止（官方编辑只接受文本块且整体替换），要给出明确提示而不是静默丢附件。
- 队列项被取走或已删除时，重读官方队列并刷新显示；不得凭本地缓存推断。

## 4. 流式与持久合并

- 流式输出是预览，不是历史；正式消息到达后替换预览。
- 失败或被取消的尝试不得留在历史里；`assistant/attempt` 语义要显式处理。
- 思考过程与正文分开呈现，过程默认低强调、可展开（沿用 ADR [`2026-10-28-nano-process-display`](../../decisions/2026-10-28-nano-process-display.md)）。
- 流式期间的渲染合并遵循 S02 的批次预算：**允许丢中间帧，不允许丢字符**。
- 断流、未知事件、解析失败都要可见：显示为「未确认 / 连接断开」并给出恢复途径，不得假装完成。

## 5. Transcript 与工具卡

- 只读渲染接口对外暴露，S05 复用同一套，不复制渲染器。
- markdown 子集：标题、列表、代码块（带语言高亮）、行内代码、强调、链接、表格。代码块内容不得被行内样式破坏。
- 工具卡显示工具名、关键参数摘要、状态（运行中/成功/失败/取消）、耗时、可展开的完整输出。
- 输出超长时按 S02 的有界策略裁剪并明确标注「已截断 + 完整内容位置」，不得静默切掉。
- 点击路径：卡片内的路径与行号可被识别为可跳转目标；跳转前校验存在性，不存在则提示而不是报错崩溃。

## 6. 文件差异

- 统一 diff 呈现：单侧全增/全删时占满整宽，不留空白对侧；普通编辑左右并排；混合文件按文件各自决定布局。
- 行号、变更标记、折叠；折叠默认策略在实施时实测确定并记录。
- 二进制、超大文件、无换行结尾等边界要显式呈现，不显示成空 diff。
- 差异内容是只读展示，不提供「直接应用」动作。

## 7. 问卷与审批

- 审批只回官方定义的四种既定结果，不自造第五种；没有有效回答时按拒绝/取消处理，**绝不默认允许**。
- 问卷答案按 `{id, selected, custom?}` 原样回传；每个问题 ID 恰好出现一次。
- 限时问卷要显示剩余时间并可取消；超时按官方 `ASK_TIMED_OUT` 结束，问题转为已继续，UI 不能停留在等待态。
- 审批与问卷互斥呈现：同一时刻只有一张决策卡获得焦点（多张排队时显示队列深度）。
- 重连后要能恢复未决卡片，不能因为断线丢失等待中的审批。

## 8. 场景、焦点与功能注册

- 场景（主对话、会话列表、终端、任务、调度、子代理）由本份定义注册形状；各功能只声明自己的场景，不改全局路由。
- 同一时刻一个活动场景、一个焦点；覆盖层优先级高于场景。
- 场景切换保留各自草稿与阅读锚点；切回时恢复位置。
- 按键派发顺序：覆盖层 → 当前场景 → 全局快捷键；全局快捷键不得抢占正在输入的文本。

## 9. 失败与不变量

| 类 | 例 | 处理 |
| --- | --- | --- |
| 未确认 | 已提交未落盘、断流 | 标未确认，给恢复途径，不自动重发有副作用动作 |
| 明确失败 | 官方拒绝、写锁被占、超限 | 保留草稿与原文，显示原因 |
| 内部错误 | 渲染抛错、未知事件 | 可见错误 + 保留数据，不丢消息 |

不变量：任何 transcript/回显/队列/附件/草稿/决策不跨会话地址出现；停止不清空队列；审批无答复即拒绝。

## 10. 验收

1. 真实模型会话：发送 → 流式 → 工具调用 → 差异 → 完成，全程可读、可中断、可重连。
2. 运行中排队、插话、删除队列项、停止（保留队列）、停止并清空（逐项删除）五条路径各有真实会话证据。
3. 断线重连：保留草稿、恢复到正确地址、未决审批仍可回答。
4. 长输出：工具输出与代码块被裁剪时标注清晰，完整内容可获取。
5. 问卷：正常回答、自定义回答、超时、取消四条路径；审批：四种结果各一条。
6. 跨地址隔离：主会话与子会话同时存在时，transcript、草稿、队列、决策互不串。
7. 差异：新增文件、删除文件、混合修改、二进制、超大文件五类各一条。

## 11. 机制清单

| 机制 | 解决什么 / 没有会怎样 | 确认与代价 |
| --- | --- | --- |
| 官方身份映射（seq / rpcId / callId / toolCallId） | 展示层需要稳定主键；用错主键会导致重复或丢消息 | 官方契约；字段名必须写清 |
| 本地回显 + 退休 | 点击即有反馈又不伪造历史；没有则界面卡住或留下幽灵消息 | 沿用 v1 S02；回显只活在本进程内存 |
| queue / steer 分义 | 用户能预期消息何时进入模型 | 官方两种投递模式；steer 是尽力而为 |
| 停止保留队列 + 复合清空 | 一次 Esc 不应丢光后续输入 | 官方 cancel 固定保留收件箱 |
| 流式预览与持久合并 | 失败尝试不得留在历史 | 官方 attempt 语义 |
| 场景注册与焦点栈 | 防止各功能私改全局路由 | 本份独占该接口 |
| 差异布局按文件各自决定 | 避免单侧变更时出现空白对半 | 沿用 v1 视觉约定 |
