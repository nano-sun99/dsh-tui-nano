# [2026-10-28-nano-ts] TypeScript 单进程重写

- 组标识：`2026-10-28-nano-ts`；角色：单份 spec，总纲与执行规格合一。
- 状态：草案。
- 上游决定：[ADR-20261028-implementation-language-typescript](../../decisions/2026-10-28-implementation-language-typescript.md)。
- 行为权威：[`2026-10-20-nano-v1`](../2026-10-20-nano-v1/README.md)（A–K 各节继续有效；仅 S01 的运行时与进程形态由本文取代）。
- 替代关系：只替代 v1 的实现语言与运行形态；不替代业务行为。旧 TS 方案（PR #83）已废弃，不沿用其子件结构。
- 适用环境：macOS arm64 + Ghostty，全屏优先。
- 官方基线：`0.2.1-rc.2`；能力快照为启动门槛，版本号只作辅助。
- 合入前提：phase-0 spike 通过（见 §8.1）；真实终端证据与 stdout 纯净证据齐全。

## 1. 目标与非目标

**目标**：在官方 DSH 核心之上，用单一 TypeScript 代码库实现 nano 的终端界面；单 Node 进程、进程内事件、无自造协议；保留 v1 已验收的业务行为。

**非目标**：

- 不重写 Agent、模型、工具、沙箱、会话、权限与持久化。
- 不做多后端（Claude / Codex）、插件市场、远程宿主、MCP 管理、检查点回滚。
- 不引入第二套视觉体系；沿用现行主题与间距 ADR。
- 不做 Rust 与 TypeScript 并存，不做「先并行再切」。

## 2. 已确认决定

| 决定 | 内容 | 影响 |
|---|---|---|
| 实现语言 | TypeScript；Rust 打 `rust-final` tag + `archive/rust-v1` 分支后退场 | 61,395 行 Rust、789 个测试退出主线 |
| 运行形态 | 单一 Node 进程；无第二进程、无 `nano.*` 协议、无 fd 3/4 | 桥接层与协议契约不再存在 |
| 组装方式 | 自己建 Cordis 根，用官方 `dsh-app-boot` 组装官方核心 profile；nano UI 挂同一根 | 不再以 `dsh --profile` 启动；phase-0 不成立时回退该入口 |
| 渲染底座 | `react-reconciler` + Yoga；不用 Ink 的渲染 / 输出 / 输入层 | 终端层自写，布局用 Yoga 子集 |
| 终端所有权 | nano 独占 fd 0/1、raw mode、resize；官方日志走 stderr 或文件 | stdout 污染即启动失败；需实测证据 |
| 行为权威 | v1 规格冻结；业务语义不变，实现重写 | 任何语义变化必须显式记录 |
| 结构 | 1 份 spec + 3 个阶段（α / β / γ） | 不拆 6 份子 spec；执行 issue 按阶段开 |

## 3. 运行结构与官方交互

```text
Ghostty
  └─ nano（本包 bin，唯一 Node 进程）
       ├─ 自建 Cordis 根
       │    ├─ 官方核心 profile（dsh-app-boot 组装）
       │    └─ nano 插件（UI / 输入 / 渲染，同一根）
       └─ 官方 DSH：Agent / 模型 / 工具 / 会话 / 权限 / 持久化
```

- **启动**：解析已安装的官方包与 `$DSH_HOME`，建立 Cordis 根，用 `dsh-app-boot` 的 `composeEntries` / `loadProfile` 组装核心；随后挂载 nano 插件并接管终端。**不启动第二个进程**。
- **直接调用**：`ctx.agents`、`ctx.sessions`、`ctx.sessionQuery`、`ctx.userQuestions`、审批 waterfall、附件、`ctx.controls`、调度、终端、任务、子代理等公开导出；没有协议与序列化。
- **直接订阅**：`session/event`、`agent/assistant-stream`、`agent/status`、inbox、决策、jobs / monitor 事件；类型来自官方 `.d.ts`。
- **事实源**：会话、工具结果、队列、权限、持久化以官方记录为准；nano 只保留展示缓存、草稿、阅读锚点，不写第二份历史。
- **能力快照**：启动时核对必需能力（会话 / 审批 / 问卷 / 附件 / 调度 / 终端 / 任务 / 子代理 / 模型 / 权限）；缺失即明确失败并给修复路径，不降级猜。
- **回退**：phase-0 spike 若证明 `dsh-app-boot` 组装不可行，回退到官方 `dsh --profile dsh-tui-nano` 入口；其余决定（TS、渲染、终端、功能）不变，并在 ADR 记录。

## 5. 渲染与输入

### 5.1 渲染宿主

- 一帧 = 计算 → diff → 生成字节 → 单次写 fd 1；禁止边算边写。
- 屏幕为 cell 二维缓冲；宽字符占两格，第二格占位；样式稀疏变更。
- 双缓冲 + 最小 diff；整屏滚动用区域滚动序列，不全量重绘；帧输出可重放。
- 虚拟化：视窗外不构建组件树；行高估算 + 按需构建；缓存有界（LRU）。
- 不承诺消除 GC 停顿或脱离 Node 事件循环；承诺渲染自身不无界增长、在实测基线内不掉帧。

### 5.2 布局子集（写死）

固定高度、内容高度、按比例分配、最小 / 最大、水平 / 垂直堆叠、溢出裁剪、粘底滚动。不做浏览器级完整 flex；各功能不自行发明布局规则。

### 5.3 输入

- 键盘：普通键、修饰键、多字节序列；kitty keyboard enhancement 可用时启用并降级。
- 鼠标：点击、滚轮、拖拽选择、分栏拖拽；分片 SGR 序列可重组。
- 粘贴：bracketed paste 作为批量输入，不逐键处理。
- 焦点：同一时刻一个焦点；覆盖层优先；Escape 逐层退出。
- 无法识别的输入可诊断（限流），不静默吞键。

## 6. 终端所有权与生命周期

- 插件获得控制权后立即接管 raw mode、resize 与 fd 0/1；官方侧不得写 stdout。
- 诊断一律写 stderr 或文件；启动全程捕获 stdout，任何非 nano 写入记为失败。
- 退出 / SIGINT / SIGTERM / SIGHUP 都恢复 raw mode、光标、备用屏幕、鼠标上报；强杀不承诺恢复，提供 `reset` 提示。
- 关停顺序：停输入 → 取消在飞请求 / 子代理 → 停监听 → 释放 PTY → 排空持久化 → 释放认领 / 租约 → 恢复终端 → 退出；任一步失败逐项报告。
- 会话挂载账本沿用 v1 S01 §2.1，只把 pid 改为本进程 pid。

## 8. 验收

### 8.1 phase-0（合入前提）

1. 自建 Cordis 根 + `dsh-app-boot` 组装官方核心成功；真实官方包、真实 `$DSH_HOME`。
2. 首帧先于模型 / 会话列表加载可见；启动全程 stdout 无官方写入（捕获证据）。
3. 创建或恢复一个真实会话，完成一轮真实模型对话；正常退出后终端属性恢复。
4. 若 1–3 任一不成立：回退官方 `dsh --profile` 入口，记录原因与证据；其余决定不变。

### 8.2 α / β / γ

- α：真实对话 / 流式 / 工具 / 差异 / 审批 / 问卷；1000 行 transcript 滚动、流式追加、resize 的 p50 / p95 实测；CJK / emoji / ZWJ / 中文输入法；鼠标点击与拖选。
- β：会话列表 / 恢复 / 压缩、附件、技能、终端 PTY、任务、Monitor、调度、子代理逐项用真实官方服务验证；不得用假数据或静态截图冒充。
- γ：全新安装 → 启动 → 卸载 → 重装；e2e 跨功能；发布矩阵；Rust 删除后仓库可构建；证据归档。
- 长会话：5000 行后内存有界（实测曲线）；错误 / 断流 / 未知状态不得显示成成功。
- 审批无答即拒；Monitor `notify` 默认关闭；人工命令提示系统权限；子代理 / 父会话内容隔离。

## 9. 风险与未决

- **官方核心组装**：`dsh-app-boot` 的 compose / loadProfile 是否足以在没有 `dsh --profile` 的情况下建立完整核心，未实测；phase-0 是硬闸，失败回退官方入口。
- **stdout 污染**：官方插件 / 日志可能写 stdout；必须实测并在 patch 中关闭，不能靠用户运气。
- **渲染工程量**：自写 cell / diff / 输入 / 虚拟化 + Yoga 版本耦合；S02 是最大工程量与最大风险。
- **JS 运行时**：GC 与共享事件循环；无崩溃隔离；ADR 已接受。
- **功能 parity**：13 个 v1 子件，月级；迁移期无可用产品。
- **官方升级**：能力快照只能发现缺失，不能发现语义漂移。

## 11. 自定细节

- 包名与 bin 名沿用 `dsh-tui-nano` / `nano`；数据根 `~/.dsh-tui-nano`；官方 `$DSH_HOME` 不动。
- 目录结构：`src/boot|runtime|render|input|theme|conversation|transcript|decisions|attachments|sessions|controls|skills|terminal|jobs|monitor|schedule|subagents`。
- `react` / `react-reconciler` / Yoga / 官方包版本在实施时选定并锁定，不在 spec 写死。
- 虚拟化窗口、缓存上限、批次大小、帧率目标由实测定，不先写死。
- 组件 API（`<Box>` / `<Text>` / `<Overlay>` 等）在实施时冻结，功能只消费。
- 备用屏幕是否启用由运行时与发布验收共同决定。
- 图片协议（Kitty / Sixel）不在本次范围；需要时另立需求。
