## 3. 定稿规则

### 3.1 过程分组

- **组内工具**：官方名为 Read、Grep、Glob、List 的调用（大小写不敏感）。其他工具不参与。
- **分组边界**：只合并 transcript 中相邻的组内调用。任何其他 entry（Bash、Edit、Write、AskUserQuestion、用户消息、notice、context、助手正文、审批记录等）都会打断分组。
- **失败 / 中断 / 未知不并入组**：这类调用自己按现有失败卡渲染，并在其前后断开分组。失败摘要继续可见。
- **入组后转失败**：如果 pending 调用在后续渲染中变成失败 / 中断 / 未知，就在该调用处断组；它自己成为失败卡，它前面的调用仍成一组，它后面的调用另起一组。组级状态因此不会出现失败 / 中断 / 未知。
- **组行内容**：
  - 单次调用：`Read <path>` / `Grep "<pattern>"` / `Glob "<pattern>"` / `List <path>`；目标取不到时退回官方名。
  - 两次及以上：按 `Read → Grep → Glob → List` 顺序计数，用 ` · ` 连接，例如 `Read 3 个文件 · Grep 2 次 · Glob 1 次 · List 1 个目录`。
- **右侧**：只显示现有状态标签中的 `等待结果`（组内仍有 pending）或 `完成`（全部成功），可展开时追加 ` · 点击展开`；展开后写 ` · 点击收起`。不显示用时。
- **展开体**：按调用顺序逐条列出目标行和该调用的结果正文；正文 muted、缩进 2ch，单条最多 `MAX_BLOCK_ROWS`。没有结果时不多造空行。
- **组身份**：取组内第一条调用的 identity；后续调用加入同组时保持不动，展开状态不因新调用到达而丢失。

### 3.2 结果行预算

- Bash 成功：输出由 2 行改为 0 行；运行中维持 0 行；命令标题与折叠态命令首行保持 1 行。
- Bash pending 的「等待结果；没有来源时不显示假输出」事实提示保留；它不是结果输出。
- 通用工具成功：结果由 3 行改为 0 行；失败 / 中断 / 未知保持 3 行。
- Bash 失败 / 中断：保持 3 行输出 + 退出状态。
- `+N 行` 继续按实际未显示的视觉行计数，覆盖命令与输出。
- File / Edit、审批、问卷、子代理的现有预算不变。

### 3.3 可发现性提示

- **适用对象**：组行、Bash 行、通用工具行。File / Edit 与 context 行沿用各自已有的「点击展开 / 已展开」提示，本次不改。
- 只有存在可展开内容时，右侧才追加 ` · 点击展开`；展开后同一位置变成 ` · 点击收起`。
- 60 列下状态词与提示都必须完整可见；左侧标题可截断为省略号。
- 更窄宽度允许省略提示，但不得省略状态词。

### 3.4 思考

- **流式**：标题 `▸ 思考 进行中…`（流结束但未提交时为 `▸ 思考 已结束`），保留可得用时；正文全量显示，muted、缩进 2ch，受 `MAX_BLOCK_ROWS` 限制；与后续正文之间保持 `Gap::Section`。
- **提交后**：不渲染任何思考行，连标题都不保留；会话恢复与历史回放同样不显示。
- 空思考不渲染。
- 已知代价：完成后没有全局入口，正文不可回看。用户 2026-10-28 明确接受。

### 3.5 不做

- 不新增全局展开 / 收起、转录模式或 `Ctrl+O` 类快捷键。
- 不改点击与拖选语义：拖选、复制优先，不触发展开。
- 不改失败、审批、问卷、子代理的业务行为。
- 不新增计时字段，不用 demo 用时冒充真实数据。

## 9. 机制清单

| 机制 | 解决什么；不做会怎样 | 代价 |
|---|---|---|
| M1 过程分组 | 连续读取 / 搜索只占一行，长任务不再被过程刷屏；不做则每读一个文件一张卡 | 展开才看到每次调用；单次调用也不再单独起卡 |
| M2 思考完成后消失 | 屏幕只留结论；不做则完成态仍占一行 | 没有全局入口时正文不可回看 |
| M3 成功结果默认 0 行 | 过程卡只留标题和状态；不做则默认屏幕被输出占满 | 想扫一眼结果要多一次点击；失败仍不隐藏 |
| M4 过程行点击提示 | 组行 / Bash / 通用工具行的展开入口可发现；不做则用户不知道能点开 | 每行右侧多几个字；File / Edit / context 已有提示，不重复改 |
| M5 流式思考正文可见 | 生成中能看到模型在想什么；不做则只有一行状态，过程不可读 | 生成期间占用屏幕；提交后随整行一起消失 |

本 spec 不新增架构层或跨任务抽象；`Unit::Group` 是现有 display unit 的内部扩展。

## 10. 自定细节

以下是 spec 未由用户逐项指定、由方案期确定的默认值：

- 组内工具固定为 Read / Grep / Glob / List；不把 Bash、MCP、ToolSearch 并入。
- 单次调用显示目标；两次及以上显示计数，不显示“最近目标”。
- 计数文案：`N 个文件` / `N 次` / `N 个目录`；顺序固定 Read → Grep → Glob → List。
- 组行与卡片右侧不显示用时；现有记录没有每工具计时。
- 失败 / 中断 / 未知调用不并入组；入组后转失败按 §3.1 断组。
- 组身份取第一条调用的 identity，保证展开状态稳定。
- 展开体包含每条调用的结果正文；没有结果时不额外造行。
- pending 的事实提示保留；它不算结果输出。
- 60 列必须同时看到状态和提示；更窄允许省略提示。
- 交互稿里的用时是演示数据，不作为验收依据。
