## 1. 目标

修复当前 Nano TUI 中“能用但用户看不懂、看不出焦点、内容一窄就乱”的一组连贯问题：

1. 空输入时让用户明确知道输入框已经获得焦点，且首次输入不改变布局。
2. 移除会在输入后消失的 `继续提问…` 占位文案，保留稳定的输入起点。
3. 把流式预览的临时性、缺失和截断用用户能理解的状态表达出来。
4. 保留“未知”状态的事实约束，但不把内部术语直接甩给用户。
5. 让 `/model` 选中 `XHigh` 时的扫光效果在真实终端中可见，并补足证据。
6. 让助手返回的 Markdown 表格在 100 / 60 列及中英文内容下保持可读。
7. 建立稳定的纵向间距节奏，避免回答、工具状态、表格、输入区互相贴住。

验收单位是终端 cell。字体、字号、终端光标样式和终端透明度继续由用户终端控制。

## 4. 交互与视觉规则

### 4.1 Composer 焦点与稳定输入起点

1. 输入获得焦点时必须同时具备两个可见信号：
   - `>` 前缀使用 accent，并保持稳定位置；
   - 终端光标位于 `> ` 后的第一个可输入 cell，即使草稿为空也要设置。
2. 空输入不再显示 `继续提问…` 或其他会随输入消失的占位句。主会话和子代理会话都使用稳定的 `> ` 输入起点；子代理名称由标题 / 状态区域表达。
3. 当终端光标不可依赖或当前焦点被其他面板占用时，composer 至少通过前缀和边框状态区分焦点：
   - 聚焦：前缀 accent / 粗体，边框使用焦点色；已知上下文占用时，已占用色段保留语义，剩余段使用焦点色；
   - 未聚焦：前缀和边框回到 muted / rule，不显示输入光标。
4. 点击输入区任意可定位位置仍恢复焦点，并把光标放在对应 cell；点击发送箭头不把焦点误画回正文。
5. 空输入与输入第一行使用相同高度，首次键入不能推动回答、状态栏或 dock 跳动。多行输入仍沿用现有上限和滚动规则。
6. 输入框仍保留上下文占用色段；本次只调整它与焦点态的组合，不恢复独立 context bar，也不在边框写百分比。

### 4.2 流式预览的用户状态

流式预览继续是临时投影，最终 assistant message 仍是完整记录的唯一显示依据。客户端保留现有 bounded preview、事件序号缺口和字节上限，不因文案调整而放开无界内存。

| 实际状态 | 用户看到的内容 | 规则 |
|---|---|---|
| 生成中且事件连续 | 正文 / 思考 / 工具参数的实时内容，加一个稳定的 `生成中` 状态 | 不显示内部的 preview、gap、revision、attempt 等词 |
| 生成中但检测到事件缺口或预览被截断 | `当前只显示部分生成内容，最终回答到达后会补全` | muted 单行，可按当前宽度换行；不把它标成失败 |
| 持久 assistant message 到达 | 只显示持久消息，临时预览和提示一起移除 | 保留阅读锚点，不重复追加同一条回答 |
| 尝试结束但没有持久消息，且官方结论可识别 | 显示官方结论或中断事实 | 不补写模型正文 |
| 尝试结束且没有可识别结论 | `未收到完整回答`，并保留已有可见片段 | 不使用“最终消息会补全”，因为此时没有最终消息可引用 |

“当前只显示部分生成内容”只在检测到实际缺失 / 截断时出现；正常流式输出不常驻这句说明。预览被替换或退休时，不改变历史、模型上下文或服务器行为。

### 4.3 工具未知状态与退出状态

状态判定不变，只改用户可见词和解释：

- `Pending`：`等待结果`。
- `Succeeded`：`完成`。
- `Failed`：`失败`。
- `Interrupted`：`已中断`。
- `Unknown`：主状态显示 `结果未确认`；同一工具块补一行 muted 解释：`工具未返回成功或失败结论`。
- Bash 缺少 `[exit code: N]`、signal、timeout 或 stopped 标记时，显示 `退出状态未返回`，不显示 `退出码未知`，不将其转成退出码 0。

未知状态使用 muted / warning 的事实提示，不使用失败红色；明确错误、非零退出码、超时和信号继续使用现有失败 / 中断颜色。完整原始结果仍可展开查看。

### 4.4 `/model` 的 XHigh 动效

1. 选中官方 `xhigh` 时，强度条保留设计稿中的深蓝填充，并在已填充区域显示一个从左向右移动的高光带；高光移动必须跨越至少两个可观察位置，不能只是固定颜色。
2. XHigh 标签保持当前档位的 accent / bold 语义；不得因为动效改变档位名称、选择结果或官方档位集合。
3. 动效只在 `/model` 打开、当前焦点是 XHigh 且未启用 reduced motion 时刷新；面板关闭、切换到其他档位、全屏终端覆盖或 `NANO_REDUCED_MOTION=1|true` 时停止刷新。
4. reduced motion 下保留静态颜色、填充比例和标签，去掉高光移动；Max 的既有脉冲也按原规则静止。
5. 真实终端证据使用确定性模型目录 fixture 提供 `Low / High / XHigh / Max`，不依赖当前账号真实目录是否声明 XHigh。证据至少要捕获两个不同 phase 的 ANSI / PTY 帧，并证明帧间变化来自 XHigh 高光而非布局抖动。

### 4.5 Markdown 表格

只把符合 Markdown 表格最小结构的连续行识别为表格：至少一行表头，紧随一行由 `-` 与可选冒号组成的分隔线，并且两行含可解析的 cell 分隔符。其他含 `|` 的普通文本继续按普通 Markdown 渲染。

表格渲染规则：

1. 去除 cell 两侧多余空格和包围管道，保留 cell 内文本；支持转义的 `\|`，不把它误当列分隔。
2. 分隔线中的 `:---`、`---:`、`:---:` 分别表达左对齐、右对齐、居中；没有冒号时左对齐。
3. 表头使用现有正文强调风格（粗体 / 主题 accent），正文使用普通 fg；列分隔符与分隔线使用 muted / rule。
4. 依据终端显示宽度计算列宽，使用 `unicode-width` 处理 CJK 和宽字符；单元格长于列宽时按 cell 内换行，续行保持列对齐。
5. 总宽超过可用宽度时优先压缩列宽并换行；仍无法容纳时对最长单元格做带省略号的可读截断。任何表格行不得溢出右边界。
6. 表格上下与普通段落之间各保留一行；表格内部不在每一行之间插空行。
7. cell 内已有的 `**…**` 强调继续可见；表格无法可靠解析时回退到原始文本的安全换行，不删除或重排用户内容。
8. 100 列验证完整表格、长单元格和中英文混排；60 列验证多列压缩、CJK 换行、表头仍可辨认和无横向溢出。

### 4.6 间距与布局节奏

间距不是给每一行都加空白，而是区分语义块和块内信息：

- 主界面左右保留 2ch 外边距。
- 标题到 transcript 保留一行空白。
- 用户消息、助手回答、思考、工具、上下文、预览、diff 等同级主块之间保留一行空白；entry 已有的末尾空行不能与新规则叠加成两行。
- 助手正文的段落、标题组、列表组和表格之间保留一行；同一列表内部、同一表格内部不插空行。
- 工具块内部保持紧凑的阅读顺序：标题 → 命令 / 结果 → 状态；diff 保持标题 → rule → 状态 → 代码，不在每个代码行之间加空行。
- composer、底部状态栏、subagent dock 之间在剩余高度允许时保留一行分隔；终端高度不足时按“先收紧分隔、再收紧过程详情、最后保留输入与错误事实”的顺序降级，不能截掉可发送输入或失败事实。
- 60 列下优先保证语义分组和可读换行；不以压缩掉所有空行换取内容塞满屏幕。

## 6. 验收标准

### Composer 与布局

- [ ] 空输入默认聚焦时可同时看到 accent `>` 和可见光标；点击输入区后焦点与光标位置正确。
- [ ] 输入框失焦时有明确的视觉降级；队列、模型面板、问卷 / 审批等焦点不会误显示为输入框聚焦。
- [ ] 界面中不再出现主会话或子代理输入框的 `继续提问…` 占位文案。
- [ ] 空输入与首次输入保持相同高度；输入第一行不会推动 transcript、状态栏或 dock 跳动。
- [ ] 100 / 60 列下左右 2ch 外边距保留；同级主块之间一行空白；内容不足高度时按既定降级顺序收紧，不丢输入和错误事实。

### 流式预览与工具状态

- [ ] 正常流式预览显示生成中状态，不显示 `preview`、`gap`、`revision`、`attempt` 等内部词。
- [ ] 事件缺口或预览截断时显示“当前只显示部分生成内容，最终回答到达后会补全”；正常流式输出不显示该警告。
- [ ] 持久 assistant message 到达后，预览和临时说明移除，不重复显示正文，阅读锚点不跳到错误位置。
- [ ] 没有持久消息且尝试结束时，按官方可识别结论显示；结论不可识别时显示“未收到完整回答”，不编造最终内容。
- [ ] 工具未知状态显示“结果未确认”及原因说明；Bash 缺失终止标记显示“退出状态未返回”，不显示成成功、失败或退出码 0。
- [ ] 明确非零退出码、错误、超时、信号和中断仍保留原有失败 / 中断事实与颜色。

### Markdown 表格

- [ ] 合法 Markdown 表格识别表头、分隔线、列对齐和正文行；表头有强调，分隔符 muted / rule。
- [ ] CJK、宽字符、长单元格、空单元格、转义管道在 100 / 60 列下均不破坏列关系。
- [ ] 60 列下表格不横向溢出；长内容换行或安全省略；表格上下与普通段落各有一行间距。
- [ ] 不完整或普通含 `|` 文本安全回退，不删除、合并或臆造内容。
- [ ] 表格 cell 内已有粗体标记仍按现有 Markdown 规则呈现。

### `/model` XHigh

- [ ] `/model` 选择官方 `XHigh` 后，强度条高光至少在两个 phase 之间移动，用户能在真实终端看到扫光。
- [ ] XHigh 选择不会改变模型、档位 ID、提交参数、焦点导航或默认态行为。
- [ ] 关闭面板、切换档位、终端覆盖和 reduced motion 时停止持续刷新；静态颜色和档位名称保留。

## 7. 机制清单

| 机制 | 解决什么 | 没有会怎样 |
|---|---|---|
| Composer 焦点可视化 | 让用户确认当前可以输入，且空输入也有光标 / 焦点信号 | 输入虽然能工作，但用户不知道焦点在哪，容易误操作 |
| 流式预览状态分层 | 把生成中的临时投影、缺失 / 截断和最终持久消息区分开 | 用户会把临时片段、警告和最终回答混成同一份内容 |
| Markdown 表格适配 | 按终端 cell 宽度重排表头、列和长单元格 | LLM 返回表格时管道和分隔线挤成普通文本，列关系错乱 |
| 统一留白节奏 | 以语义块为单位控制上下间距和窄屏降级 | 外层有边距但内部信息互相贴住，页面密度失控 |

## 8. 自定细节

以下细节不是用户逐条指定，而是为使 spec 可实施而暂定；实施时不得把它们扩成新机制：

1. 使用当前 `> ` 作为唯一稳定输入起点；不再引入“输入消息”“继续提问”等常驻占位标签。
2. 聚焦态优先使用 accent 前缀、终端光标和边框色三个已有视觉角色，不新增输入框专属图标或按钮。
3. 未知工具状态的用户文案采用“结果未确认”和“工具未返回成功或失败结论”；Bash 采用“退出状态未返回”。
4. 预览缺失 / 截断统一采用“当前只显示部分生成内容，最终回答到达后会补全”；尝试无持久结论时采用“未收到完整回答”。
5. 表格最小识别结构是“表头 + 紧随分隔线”；不引入第三方 Markdown 依赖，沿用当前渲染器和 `unicode-width`。
6. 表格列分隔使用现有终端可读的 muted / rule 字符角色；不增加外框、卡片阴影或网页式操作按钮。
7. 60 列表格优先换行，无法容纳时才截断；截断统一使用省略号，不横向滚屏。
8. 主块间距默认一行，块内工具 / diff 保持紧凑；高度不足时先收紧空白和过程详情，不收紧输入与错误事实。
9. XHigh 真实证据使用确定性 fixture 暴露官方样式数据；不新增生产协议字段，也不把 fixture 当官方模型目录。
10. 本次沿用 `NANO_THEME=dark|light` 和 `ADR-20261022-independent-tui-theme` 的主题边界；如实现证明需要新增长期主题决策，先暂停并另走 ADR 判断。
