## 1. 目标

让问卷卡（单选 / 多选 / 多题）与设计稿**逐项一致**，而不是「看起来差不多」：

1. **形态**：卡片占用输入位（就地），顶部一条 accent 线，无外框；transcript 保持可见。
2. **可读**：单列编号 + 独立焦点指针 + 选项描述另起一行（5ch 缩进，只渲染一次）。
3. **可选**：焦点与已选视觉分离；数字 1–9 直选；`其他` 是第 N+1 行，↑↓ 可达、直接键入。
4. **可交**：多题有题签（`[x]/[ ]` 完成态）可来回看，末尾有提交页；缺项拦截并跳回第一道未完成题。
5. **可退**：`Esc` 取消整次提问（不提交任何答案），`Alt+N` 跳过本题（提交空数组）。

### 非目标

- **倒计时 / `askTimed`**：设计稿无此形态；接 `attachWait` 需单独 spec。
- **审批卡**：本 spec 只保证不被问卷卡改动破坏；审批卡的视觉/交互另立。计划审阅虽与问卷共用一张卡，本次只按 §3.11 保底（`intent` 分支 + `detail` 区 + 「(批准)」标记），不做专门版式。
- **只读回看、跨窗口 `answer` 回填**：S03 已有条款，本次不重做，只保证不回归。
- **模型侧提问提示词**：不要求模型改行为（推荐项排第一仍是模型约定，不由 UI 代劳）。

## 3. 交互规格

### 3.1 槽位与形态

- 卡片渲染在 **transcript 与状态行之间**，占输入位；待答期间输入行隐藏，等待文案走**底栏中段 notice**（「等待你的选择」），复用 `StatusLine` 既有瞬态通道，不新增槽位（`src/app/App.tsx:186-191`、`src/app/nano-app.ts:641-643`）。
- 顶部一条宽度 = `屏宽 − 4ch` 的 accent 线；无外框、无圆角、无底色块。
- 卡片总高 ≤ `min(20 行, 终端高 − 12)`；页脚固定贴底，中间 body 可滚动。
- 只允许一张卡片持有焦点；子代理地址的卡不跨地址作答（沿用 S03 §4.11）。

### 3.2 行结构

```
> 1. [x] 窄终端                      ← 多选题
> 2.     完整回归                    ← 单选题（无复选框）
        覆盖本次修改相关的检查。      ← 描述：5ch 缩进、muted、只一次
  4. 其他：直接输入▏                 ← 第 N+1 行：永远没有复选框，输入态显示光标
```

- 指针 1ch（`>` / 空格），编号 2ch（`1.`），多选复选框 4ch（`[x] ` / `[ ] `）。
- 描述行永远在选项下一行，缩进 5ch，`muted`；**不得**同时出现在 label 行尾。

### 3.3 焦点与选中

| 状态 | 表现 |
|---|---|
| 焦点 | 行首 `>` + 整行文字 `accent` + 粗体；焦点行不改变选中态 |
| 已选（单选） | 行尾 `✓`，文字 `success` + 粗体；行首指针为空 |
| 已选（多选） | 复选框 `[x]`，文字 `success` + 粗体 |
| 焦点 + 已选 | 同时显示：`>` 在行首、`✓`/`[x]` 保留，颜色以焦点为准，`✓` 仍为 success |

- 焦点初始 = 第 1 项（不是第 0 号「其他」，也不预选任何项）。
- 回到已答题目时：焦点停在该题上次的位置、已选标记保留（设计稿按题保存 `focus`，`choices.js:59-61`、`:93-97`）。

### 3.4 单选

| 操作 | 行为 |
|---|---|
| `↑` / `↓` | 在「选项 + 其他」之间循环移动 |
| `1`–`9` | 直选第 N 项并前进（单题即提交，多题即翻下一题）；按 `N+1` 等于把焦点移进「其他」行 |
| `Enter` | 选中焦点项并前进 |
| `Space` | 等同 `Enter`（选中焦点项） |
| 点击选项 | 选中并前进（与 Enter 同义） |

### 3.5 多选

| 操作 | 行为 |
|---|---|
| `↑` / `↓` | 在「选项 + 其他」之间循环移动 |
| `Space` | 切换焦点项勾选，焦点不动 |
| `Enter` | 至少选 1 项时前进；0 项时报「请至少选择一项。」且不前进 |
| `1`–`9` | 切换第 N 项勾选（不前进）；按 `N+1` 等于把焦点移进「其他」行 |
| 点击选项 | 切换勾选（不前进） |

- 多选不预选、不提供全选/反选；不使用「已选 N 项」计数（设计稿没有）。
- 选项区下方固定一行可点按钮：单题文案「确认已选项」，多题文案「下一题」（5ch 缩进、`accent`）。

### 3.6 其他（自定义答案）

- 「其他」始终存在，作为第 `N+1` 行，参与 ↑↓ 循环。
- 焦点落在该行即进入输入态：直接键入、`Backspace` 删除、光标可见。
- 单选：提交其他答案时清空已选选项；选任一选项时清空其他答案（互斥）。
- 多选：其他答案与已选标签并存，结果同时带 `selected` 与 `custom`。
- 空内容 `Enter`：报「请填写其他答案，或选择一个选项。」；多选且已勾选时改为前进。

### 3.7 多题与提交页

- 题签：每题一个 `[x] 标题` / `[ ] 标题`，末尾一个「提交」题签；当前题 `accent` + 粗体。
- 题签宽度自适应：空间不足时先截断标题，再退化为只显示当前题；60 列下最多两行。
- `Tab` / `Shift+Tab` / `←` / `→` 在题与提交页之间循环。
- 最后一题前进 = 进入提交页（不是直接提交整批）。
- 提交页内容：标题「提交这组答案」；逐题回执 `[x] 标题` + 下一行 4ch 缩进的答案摘要；未答题显示「尚未回答」并用 `error` 色；底部「提交答案」按钮 + 页脚。
- 提交页 `Enter` 或点按钮 = 校验 → 通过则提交；缺项则跳到第一道未完成题并报「请先回答这一题。」。

### 3.8 校验

| 时机 | 规则 | 文案 |
|---|---|---|
| 多选前进 | 至少 1 项或非空其他 | 请至少选择一项。 |
| 其他行回车 | 单选必须非空；多选允许已勾选时留空 | 请填写其他答案，或选择一个选项。 |
| 提交页提交 | 每题都要有答案或被显式跳过 | 请先回答这一题。 |

- 校验失败：错误行用 `error` 色显示在页脚上方，焦点回到该题第一项；卡片不关闭。

### 3.9 取消与跳过

- `Esc`：取消整次提问，**不提交任何答案**，卡片关闭并在底栏 notice 显示「已取消，未提交答案」；`DecisionManager` 以 `waiter.reject({ name:'UserQuestionError', code:'ASK_ABORTED', message:'ask_user_question was aborted before the user answered' })` 结束等待，官方 `restoreUserQuestionError` 会还原成 `UserQuestionError`（见 ADR 与 §5）。
- `Alt+N`：跳过当前题（该题记 `{ id, selected: [] }`），前进到下一题；跳过不参与校验。
- 输入态下 `Esc` 仍是取消整次（不退回选项行）。

### 3.10 滚动与鼠标

- `PageUp` / `PageDown` 滚动卡片 body（±5 行）；焦点行始终自动滚入视野。键位出处是 `design-contract` §2（设计稿的问卷卡没有这两个键，只有审批命令区有滚动）。
- 提交页内容超出时同样用 `PageUp` / `PageDown` 滚动（设计稿在提交页用 ↑↓，这里让位给题签导航）。
- 点击题签切题、点击选项选择、点击「提交答案」提交；鼠标与键盘共用同一状态机。

### 3.11 计划审阅分支（`intent.kind === 'plan-review'`）

- 同一张卡，不另起版式：标题优先用 `header`，缺省「计划审阅」。
- `question.detail` 渲染在题干下方（Markdown → 纯文本行，最多 14 行，超出显示「还有 N 行」），保留现有 `App.tsx:430-433` 的能力。
- `intent.approve` 指向的选项在标签后追加「(批准)」，其余为拒绝项；提交结果与普通问卷完全一致（不新增字段）。
- 不引入「查看/批准/修改」三按钮版式——设计稿未展示，S03 §5 的紧凑卡留待审批卡 spec 处理。

### 3.12 键位总表

| 键 | 场景 | 行为 |
|---|---|---|
| `↑` / `↓` | 选项区 | 移动焦点（循环，含其他行） |
| `1`–`9` | 选项区 | 单选直选并前进 / 多选切换勾选 |
| `Enter` | 选项区 | 单选选中前进；多选校验后前进；其他行确认输入 |
| `Space` | 选项区 | 同 Enter |
| `Tab` / `Shift+Tab` | 多题 | 切题（含提交页） |
| `←` / `→` | 多题、非输入态 | 切题 |
| `PageUp` / `PageDown` | 卡片 | 滚动 body |
| `Alt+N` | 任意 | 跳过本题 |
| `Esc` | 任意 | 取消整次提问 |

## 4. 视觉规格

| 项 | 值 |
|---|---|
| 外边距 | 左右 2ch（沿用 design-contract §4） |
| 顶线 | 1 行 `─`，`accent`，宽度 = 屏宽 − 4ch |
| 行距 | 顶线后 1 行留白；题签与题目之间 1 行；选项区与页脚之间 1 行 |

| 焦点色 | `accent`（深色 `#7da1de` / 浅色 `#365f9d`，见 `src/theme/theme.ts:50`、`:79`） |

## 7. 机制清单

| 新增机制 | 解决什么；没有会怎样 | 代价 |
|---|---|---|
| 卡片内滚动位置（`scrollOffset`） | 长选项/长描述不溢出屏幕；没有就只能截断，用户看不到后面的选项 | 多一处状态，滚动与焦点联动需测 |
| 题签回看 + 提交页 | 多题答错可回改、提交前可整体复核；没有就只能单向推进 | 多两个界面态，键位增加 Tab/←→ |
| 取消语义（aborted） | 用户能明确拒绝回答；没有就只能「跳过」，模型会误以为用户答了空 | 改 S03 §4.5/§4.6 口径，工具侧会收到一次错误而非空答案 |

不新增机制：等待/取消文案复用底栏 notice 通道，不新开「活动行」槽位（见 §3.1）。

## 8. 自定细节

- 提交成功后不在卡片里画回执面板：卡片关闭，底栏 notice 显示「已回答 N 题」两秒，记录由 transcript 的工具行承担（设计稿的回执是浏览器演示态，TUI 已有工具行）。
- 提交页标题右侧追加「还差 N 题」提示（N>0 时）。依据：多题只给「尚未回答」而不给总账时，用户会误以为卡死（Claude Code 的 VS Code 版曾出现同样问题，见调研笔记 §1）。该提示画在提交页正文里，不依赖 notice。
- 题签标题超宽按「当前题优先、其余至少 6 列、最后退化为当前题前 3 字」处理（借鉴 Claude Code 的宽度退让策略）。
- 数字直选上限 9：官方每题选项上限 4 + 其他 = 5，留余量；焦点在其他行时数字是文本，不做直选。
- 错误提示出现后不自动消失，下一次有效操作清除。
- `Alt+N` 沿用 design-contract §2 已冻结的键位，不新增键。

来源：本机 `…/Downloads/归档/06-软件与安装包/ClaudeCode/src`（编译产物，行号为物理行），以及设计稿 `preview/choices.js`。

| 点 | Claude Code 做法 | 设计稿 | 本 spec |
|---|---|---|---|
| 卡片位置 | 就地嵌在消息流（`FullscreenLayout` overlay 槽） | 占输入位、顶部 accent 线 | 取设计稿：占输入位，transcript 不被盖住 |
