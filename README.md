## 这是什么

[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（`dsh`）负责 Agent、模型、工具、会话、权限与持久化。nano 不重写这些能力，只做一层终端界面：

- **一个 TypeScript 代码库**：nano 自己建 Cordis 根，用官方 `dsh-app-boot` 的 `boot()` 组装 DSH 核心，UI 作为同根插件运行。
- **单一运行时宿主**：runtime 是一个 Node 进程，拥有官方服务、会话与业务状态；CLI 入口只做一次 fd 守护包装（stdout/stderr 绑到日志，终端走独立 `/dev/tty`）。
- **无自造协议**：直接调用官方公开导出、直接订阅官方事件，没有跨进程帧格式。

设计上只做三件事：**阅读优先、少装饰、不伪造事实**。会话、权限、模型和工具结果的所有权始终在官方 DSH；nano 只显示回执和状态。

## 功能

- **对话**：多行输入、流式输出、排队 / 插话 / 停止、按地址保存草稿、恢复会话。
- **阅读与决策**：工具调用、文件差异、问卷、审批、计划卡；过程默认低强调，按需展开。
- **输入增强**：`@file` 引用、图片 / 通用文件附件、技能目录、项目规矩来源。
- **工作流**：`!` 人工命令、任务面板、交互终端、Monitor 任务输出监听。
- **会话与控制**：会话列表 / 恢复 / 改名、上下文占用、`/compact`、定时任务、子代理。
- **模型与权限**：`/model` 选模型与推理强度，`/permission` 选权限预设，`Ctrl+P` 命令面板。

## 环境要求

| 项目 | 要求 |
| --- | --- |
| 系统 / 终端 | macOS arm64 + Ghostty（唯一验证组合；其他环境未验证） |
| Node | ≥ 22.19（`engines` 声明；入口运行时检查，低于下限给可操作错误并退出） |
| 官方 dsh | 精确 `0.2.1-rc.2`；未知版本拒绝启动 |
| 凭据 | 由官方 dsh 在 `${DSH_HOME:-~/.dsh}` 解析；nano 不复制、不显示凭据值 |

数据根默认 `~/.dsh-tui-nano`（可用 `NANO_DATA_ROOT` 覆盖）：应用自持 profile、会话、运行时数据、历史与日志都在这里。`$DSH_HOME` 中 nano 只写 `.anonymous-user-id`，其他不改不删。

## 安装、升级与卸载

```sh
# 安装 / 升级
npm install -g dsh-tui-nano

# 日常卸载：删包与 bin，保留数据根与应用 profile
npm uninstall -g dsh-tui-nano

# 连数据一起删：先 purge（bin 仍在时），再卸载
nano purge          # 交互确认
nano purge --yes    # 非交互环境跳过确认
npm uninstall -g dsh-tui-nano
```

- 普通卸载**保留**数据根与 profile；只有 `nano purge` 会删除 profile、会话、运行时数据与历史。
- `nano purge` 不依赖 npm 的生命周期脚本（npm v7 起不保证 uninstall 脚本运行），所以顺序必须是「先 purge、后卸载」。
- 首次启动自动初始化应用 profile；升级时逐文件校验，损坏先备份再报错，不覆盖用户 settings。

## 主题与透明

- `NANO_THEME=dark|light` 选择 Nano 自有界面的配色，默认 `dark`；启动时读取一次，修改后重启生效。
- 自有文字、边框、状态、焦点和 diff 输出固定 RGB，不依赖终端的 ANSI 调色板或默认前景。
- 普通背景保留终端默认背景：壁纸、透明度和模糊照常生效；Nano 不铺整屏实色。
- diff、选择、hover 等局部高亮使用 Nano 自己的 RGB；它们是否参与透明合成由终端决定（Ghostty 的 `background-opacity-cells`）。
- 内嵌终端保留子程序自己的显式颜色，不做全屏改色。
- macOS 原生全屏会禁用背景透明；要在半透明窗口里使用，请用普通窗口。
- Nano 不读取、不修改你的 Ghostty 配置。

## 架构

```text
Ghostty
  └─ nano launcher（fd 守护包装，不持业务）
       └─ runtime（本包 bin，唯一 Node 宿主 / 终端写入者）
            ├─ 自建 Cordis 根
            │    ├─ 官方核心 profile（应用自持，dsh-base + 官方行）
            │    └─ nano 插件（UI / 输入 / 渲染，同一根）
            └─ 官方 DSH：Agent / 模型 / 工具 / 会话 / 权限 / 持久化
```

顶层目录：

| 路径 | 内容 |
| --- | --- |
| `src/` | nano 的全部实现：boot / runtime / render / input / conversation / 各功能面 |
| `scripts/` | 键位文档生成与发布前检查 |
| `tests/` | 单元测试、功能面测试、发布级 e2e |
| `packaging/` | npm 发布与安装说明（仓库内只保留 npm 一条安装路径） |
| `docs/specs/` | 规格与验收标准 |
| `docs/release/` | 发布验收、证据与已知限制 |

## 已知边界

- **无崩溃隔离**：UI 与业务在同一个 Node 进程里，渲染或业务异常会一起结束；崩溃后靠官方会话持久化恢复。
- **共享事件循环上限**：渲染、输入与官方 Agent 共用一个事件循环，重负载下延迟会互相影响。
- **强杀后终端可能残留**：`SIGKILL` 无法被捕获，raw mode 与备用屏可能留在终端里；下次启动会检测脏状态并提示 `reset`。
- **调度没有暂停 / 恢复**：停止任务只能删除；投递**非严格一次**，可能重复。
- **Monitor `notify` 会计费**：默认 `quiet`（官方 inject，不唤醒、不新建 turn，内容随下一次请求计费）；切到 `notify` 会唤醒模型并产生费用。
- **三处与 v1 不同的行为**（用户 2026-10-28 明确保留）：Monitor 默认 `quiet`；冷会话改名允许先取写权限（走受控重启）；权限切换失败保留原值并提示「可能已部分生效，请重开 /permission 核对」。
- 只接受官方 dsh `0.2.1-rc.2`；未知版本直接拒绝启动，不猜字段、不降级。
- `@file` 只插入路径，不读取文件内容；模型仍需调用文件工具才能读取。
- 强杀、断电和主动逃逸的后代进程不作清理保证；nano 只负责本窗口拥有的进程组。

完整清单见 [`docs/release/0.2.0/known-limitations.md`](docs/release/0.2.0/known-limitations.md)。

## 开发与测试

```sh
npm ci
npm run build
npm test           # tests/unit（S01）+ tests/feature（S02）
npm run test:e2e   # 发布级安装/卸载/启动 e2e（合成 HOME/DSH_HOME）
npm run lint
npm run keymap:docs -- --write   # 改了键位后重写 README 的键位区块
```

`scripts/keymap-docs.mjs --check` 挂在 `prepack`：README 键位区块过期时 `npm pack` 会失败。发布前检查见 `scripts/prepack-check.mjs`。

真实 Ghostty 截图验收需要桌面权限，按需手动跑；自动化回归默认走无头 PTY，不抢焦点、不动剪贴板。所有集成测试使用临时 `DSH_HOME` 和数据根，不读写用户的真实会话。
